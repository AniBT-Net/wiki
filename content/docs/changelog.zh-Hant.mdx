AniBT Wiki 與站點功能的變更紀錄；僅收錄與文件直接相關、可核驗的事實。

<Callout type="info">
  日期按北京時間（UTC+8）。較新的更新在前。同一天內按 **新增 / 修復 / 安全 / 最佳化 / 變更 / 文件 / 運維 / 資料** 分組。
</Callout>

## 2026 年 8 月 15 日

### 修正

- **字幕組資源選單移除無效的「同步到平臺」入口**
  字幕組資源列表的單筆操作選單不再顯示「同步到平臺」。只移除這一處無效入口；資源釋出後的平臺同步、後台重試與其他同步入口維持不變。

- **開坑頁封面改回同站反代，不再觸發 Mixed Content**
  `/claims` 等頁面仍使用 `/img/bgm/subject/<id>/w*.webp`。命中時站點直接回傳 WebP，不再 302 到 `r2.anibt.net/img_bgm/`，也不會再跳到 `http://` 佔位圖。未命中仍入隊後台轉碼，並相對跳到 `/loading-v6-static.webp`。首頁等已走 `anime_covers/` 公開物件的封面不受影響。

## 2026 年 8 月 14 日

### 優化

- **公開頁不再把種子地址交給搜尋引擎**
  `robots.txt` 禁止抓取 `/release/`、`/other-release/`、`/magnets`、`/search`、`/rss/` 和 `/api/`。sitemap 只保留首頁、字幕組、開坑、友鏈和關於，以及 1940 年起的番劇頁。磁力列表、搜尋和發布詳情帶 `noindex`。可收錄的番劇 / 字幕組頁不再輸出 `magnet:` 或 `/api/torrent/` 連結。RSS 訂閱地址不變，只是不被搜尋引擎當網頁收錄。

### 安全

- **站點不提供 TOTP / 二次驗證**
  登入只保留信箱驗證碼、密碼、OAuth 與可選 Passkey。`/auth/two-factor` 會 404。帳號安全頁沒有「啟用 2FA」。

### 變更

- **公開圖代理不再在站點行程裡轉碼**
  `/img/ext/*` 與 `/img/bgm/*` 未命中時不再現場抓源跑 sharp。未知來源仍 400。命中時的同站反代見 8 月 15 日修正。

### 修正

- **週表跨日後仍保留下週四播出**
  同步改為連續拉取兩段官方 7 天視窗（共 14 天）。時間表仍從今天起只展示 7 天，但週四同步的資料已覆蓋次日滾到週五後的 08/20，不再出現「下週四暫無播出」。

- **週表空日按密封視窗刪除完結檔**
  一次成功的 14 天官方視窗會覆蓋視窗內每一個上海日期：當天 0 條事件就刪掉舊播出，完結或官方停更的作品會從時間表消失。只有整次同步失敗、沒有寫出視窗時才保留舊資料。跨季續播會合併兩份 `schedule[]`，不再按作品丟掉第二季的日期。

### 變更

- **週表只在首頁，`/seasonal` 週表位址會跳回 `/`**
  當前季度的週表 HTML 只保留 `/`。開啟 `/seasonal` 或 `/seasonal?view=weekly` 會 301 到 `/`。海報牆仍在 `/seasonal?view=grid`。

## 2026 年 8 月 13 日

### 變更

- **Nyaa 代發說明統一 20000 字上限**
  提交到 Nyaa 的說明（自訂 `nyaaDescription` 與繼承本站 `notes`）現在都受 20000 字限制。超限時釋出頁會阻止提交並提示改用自訂說明；API 在釋出前返回校驗錯誤，不再把超長 MediaInfo 整段送到 Nyaa。本站 `notes` 仍可更長。詳見 [Nyaa 代發](/docs/nyaa-proxy)。

### 修正

- **公開週表依當天真實播出時刻展示**
  `/` 與 `/seasonal` 時間表現在使用 bgm.wiki 視窗裡的實際播出事件：同一部作品可以出現在多個日期，時刻與集數跟官方排期走，不再用上一週檔期做 `+7` 天推算。某一天官方已無該作品時會從當天消失。

## 2026 年 8 月 11 日

### 修正

- **RSS 釋出時間統一為上海時區**
  公開 anime、group、magnets、other 與個人訂閱 RSS 的標準 `<pubDate>` 現統一使用 RFC 822，並明確輸出 `Asia/Shanghai` 的 `+0800` 偏移；torrent 元資訊內嵌的 `<pubDate>` 使用 RFC 3339 `+08:00`。RSS URL、TTL、ETag 與 304 語義不變。

## 2026 年 8 月 9 日

### 運維

- **邊緣快取與 RSS 通知執行面遷移到私網 Bun/SQLite**
  AniBT 已將快取失效、CDN warming 與 RSS→Telegram 排程從舊 Cloudflare Worker/D1/Queues 遷移到 Dokploy 管理的單一 Bun 服務。Convex 使用持久化 wake 重試，服務在回傳 `202` 前寫入 SQLite，並由互不阻塞的 intake/purge runner 恢復未完成工作。舊 Worker、D1、Queues/DLQs、Custom Domain 與專用 WAF 已退役。公開 RSS URL、XML 欄位、TTL、ETag、304 語義及使用者呼叫方式不變。

## 2026 年 8 月 8 日

### 變更

- **字幕組圖床刪除改為可查詢的嚴格生命週期**
  刪除請求現在回傳 HTTP `202` 與穩定 operation，重複請求會重用同一刪除鏈路；圖片會立即從站內活動讀取路徑隱藏，介面區分處理中、完成和失敗。`complete` 只在 AniBT R2 物件已驗證不存在，且短連結頁面與 `i.anibt.net` 直連在 AniBT 控制的 Cloudflare 快取中完成收斂並回傳 `404` / `410` 後出現。獨立加速連結、瀏覽器快取和第三方副本不在完成範圍內。詳見 [字幕組圖床](/docs/image-host)。

### 修正

- **公開 RSS 重新整理策略收口**
  同時解析出 `bgmId` 與 `groupSlug` 的 anime，兩組 Redis 家族和 CDN 變體作為同一釋出結果一起重新整理，不再出現只更新一個 owner 的中間狀態。字幕組建立、規範 slug 重新命名與刪除會收斂舊/新完整路徑及其 `404` 負快取；日常釋出仍保持 owner 範圍。other 的 `groupId`-only 過濾跟隨 category 重新整理，帶 `q` / `search` 的全文搜尋繼續按 600 秒 TTL 獨立管理。URL、XML 欄位、TTL、ETag 與 304 契約不變。

## 2026 年 8 月 7 日

### 修正

- **自訂釋出標題範本權限與預設狀態**
  字幕組成員均可讀取本組自訂釋出標題範本；建立、修改、排序或刪除僅限組 owner 與管理員。刪除目前預設範本時，系統在同一交易中清除預設參照並寫入稽核紀錄，不保留指向已刪除範本的設定。範本名稱、內容長度與排序完整性統一在服務端驗證。

## 2026 年 8 月 6 日

### 修正

- **公開 RSS 實體失效只認權威 owner**
  anime / group / other RSS 的 CDN membership 現在由 Web 在解析 canonical owner 後隨最終響應附加，舊的 URL-derived Cloudflare Response Rules 已退出。other free-text search、anime 未解析 owner 的空 `200` 與 group 未知 owner 的 `404` 不再被虛假實體標籤誤清；dual-owner anime 仍可由 `bgmId` 或 `groupSlug` 任一真實 owner 精確重新整理。URL、TTL、ETag 與 304 契約不變。

### 最佳化

- **公開 catalog API 分階段進入 Cloudflare edge**
  `/api/anime/lookup`、`/api/mikan/group-lookup` 與 `/api/bgm/search` 在 sealed representation、容量及濫用防護門通過後逐端點加入共享 edge cache。成功響應與 BGM 權威空結果可 `MISS → HIT`，GET、HEAD 與 304 共用 ETag；重複參數、找不到/衝突、上游、限流與伺服器錯誤繼續 `no-store`，不會擴大整個 `/api/*` 的快取範圍。查詢參數順序不改變快取身份，Cookie 也不會造成公開物件碎片化。

### 文件

- **公開 RSS / catalog exact-body 條件請求契約上線**
  anime / group / other / magnets RSS 與 7 個 catalog API 現在從最終 JSON/XML UTF-8 bytes 計算 opaque SHA-256 weak ETag；GET、HEAD 與匹配 `If-None-Match` 的 304 共用同一快取 representation。公開 RSS 已移除請求時間 `lastBuildDate`；`/api/seasons/anime`、`/api/anime/groups` 的 `ts` 改為快取 representation materialization time，並進入正文與 ETag。目前這些端點省略 `Last-Modified`。anime 未解析 owner 仍可能空 `200`，group 未知 owner 仍 `404`；本次沒有擴大另外 3 個 API 的 Cloudflare edge eligibility。

## 2026 年 8 月 4 日

### 新增

- **個人資料 OAuth 應用自助管理**
  一般使用者現在可在個人資料的響應式對話框中直接建立和管理 OIDC OAuth 應用程式，無需管理員審核，也沒有獨立建立頁面。支援 Web / BFF 與原生應用程式、精確回呼網址、自助授權範圍、一次性零重疊密鑰輪換、停用 / 恢復、撤銷授權與刪除；Dynamic Client Registration 繼續關閉。OIDC 文件已整理為獨立模組，包含[概覽與欄位說明](/docs/oidc)、[第三方業務接入指南](/docs/oidc/integration)和[AI / Agent 接入參考](/docs/oidc/ai-reference)。

## 2026 年 8 月 3 日

### 新增

- **AniBT OpenID Connect 身份平台**  
  上線 `oauth.anibt.net` 標準 OIDC issuer，支援 Authorization Code + PKCE S256、pairwise `sub`、明確 scope 同意、opaque access token、refresh rotation / reuse protection 與 RP logout。Dynamic Client Registration 保持關閉；synthetic 郵箱不會對外釋出，賬號安全撤銷會持久化清理 Hydra session。詳見 [使用 AniBT 登入第三方應用](/docs/oidc)。

## 2026 年 7 月 30 日

### 安全

- **MediaInfo 純文字安全遷移**  
  釋出詳情的 MediaInfo 統一為 UTF-8 純文字：主站 GET/HEAD 返回 `text/plain` 與 nosniff，頁面只按文字顯示。生產 Agent 改用 `mediainfo --Output=Text`，並強制驗證 qBittorrent TLS 憑證；歷史 `.html` 參照與物件已全部轉為可讀文字並完成零殘留清理。

- **RSS 輸出編碼加固**  
  公開 RSS 的 Markdown 連結與圖片 URL 繼續使用獨立屬性編碼和安全協議策略；此邊界與釋出詳情頁恢復原始 HTML 相互獨立。

### 修復

- **釋出說明原始 HTML 支援恢復**  
  番劇與其他類釋出說明、詳情和預覽再次按 Markdown + 原始 HTML 渲染；`details`/`summary`、表格、圖片、連結、`div`/`span`/`font` 與行內 style 等歷史排版繼續可用。頁面不啟用 sanitizer；編輯邊界仍是字幕組成員、管理員及受控釋出 API Key。

## 2026 年 7 月 25 日

### 修復

- **公開 RSS 參數順序與 CDN 快取一致**  
  僅原始 query 參數對順序不同的 magnets、anime、group 與 other RSS 現在直接返回同一規範 200；self URL、ETag 與快取身份保持穩定，目前公開 RSS 省略 Last-Modified。預設值、相容別名、大小寫 / 空白 / 編碼差異仍返回 308；非法重複參數保持應用 400 + no-store，非法 limit 在生產邊緣可先返回 Cloudflare 403。

### 安全

- **個人訂閱 RSS 私有快取契約**  
  `/rss/subscriptions.xml` 的成功、缺少或無效憑證、限流與服務端錯誤響應統一返回 `private, no-store` 和兩層 CDN no-store；該私人 feed 不提供公開 ETag 或 If-None-Match 304 契約。

## 2026 年 7 月 24 日

### 最佳化

- **RSS 實體快取即時失效**  
  番劇、字幕組與其他類公開 RSS 在釋出事件完成 Redis 家族失效後，會按 `bgmId`、`groupSlug` 或 category 一次清除同實體全部 Cloudflare CDN 參數變體。介面 URL、TTL、ETag 與 304 契約不變；magnets 搜尋及搜尋 Redis 身份繼續按原 TTL 管理。

## 2026 年 7 月 22 日

### 新增

- **番劇釋出刪除 API**  
  新增 `DELETE /api/releases/{releaseId}` 與 `GET /api/releases/{releaseId}/deletion`。V1 僅支援 `rel_*`；DELETE 不接受 query 或請求本文，返回穩定 `rdel_*` 回執並以 200/202 表示 completed/pending。completed 僅在站內主記錄、詳情 / 種子、Typesense、magnets、公開 / 訂閱 RSS、Redis、Cloudflare 和 AniBT R2 完成不可見性驗證後出現。外站帖子、Tracker 與客戶端已快取內容不在召回範圍內。詳見 [刪除釋出](/docs/open-api/releases-delete)。

### 安全

- **字幕組 API Key scopes**  
  API Key 現在明確選擇 `releases:publish` / `releases:delete`（至少一個）；舊 Key 安全遷移為僅 `releases:publish`。釋出要求 `releases:publish`，刪除及狀態查詢要求 `releases:delete`；`/api/subtitle-groups/me` 與 publish whoami 會返回 `apiKeyId`、`apiKeySuffix` 和 `scopes`。

- **認證安全與 OAuth 穩定性**  
  Better Auth 升級到 1.6.23；CAPTCHA ticket 改為精確路徑匹配與原子一次性消耗，註冊 / 登入旁路繼續關閉。KUNGal token exchange 使用標準 form-urlencoded；OTP、驗證、重設與歡迎郵件進入可重試郵件佇列，不再同步等待外部郵件 provider。

### 最佳化

- **賬號註冊與 session 恢復**  
  郵箱註冊改為「傳送驗證碼 → 原子驗證並建立 session → 在 session 內登記密碼」。密碼格式錯誤不消耗驗證碼；驗證或密碼登記遇響應遺失可冪等重試，未過期流程整頁重新整理後也能繼續。公開頁只在伺服器明確確認無 session 後顯示登入入口，臨時網路 / 5xx 不再造成假登出。

## 2026 年 7 月 21 日

### 最佳化

- **圖床批次上傳、延遲與進度**  
  準備上傳改為每批最多 5 張，只做一次成員校驗與一次批次控制面交易；同批狀態輪詢合併為一次 GET 與一次 Convex query。R2 PUT 的 ETag 會隨任務傳給 worker，用 If-Match 單次條件讀取取代 staging 讀前 / 讀後 HEAD。支援的瀏覽器會先預縮放明顯可縮小的超大靜態 JPEG/PNG/WebP；動畫、HEIC/HEIF 等仍由 worker 處理。單圖限制仍為 10 MiB。

## 2026 年 7 月 20 日

### 最佳化

- **圖床直傳與隔離轉碼**  
  字幕組圖床改為瀏覽器直傳 staging R2；主站 Web 只負責鑑權、預簽名、物件核對和狀態查詢，不再讀取圖片二進位或執行轉碼。shared Bun worker 為每張圖啟動短生命週期子程序，用原生 `Bun.Image` 直接寫入 `Bun.S3File`。靜態圖損壞或轉碼失敗會明確失敗；動畫與 SVG 繼續保留原格式。詳見 [字幕組圖床](/docs/image-host)。

## 2026 年 7 月 19 日

### 修復

- **Tracker 固定入口恢復**  
  AniBT Tracker 已恢復固定 `https://tracker.anibt.net/announce`，不保留 signed 雙軌。既有站內種子不需更換地址或重新下載；magnet、RSS 與 canonical `.torrent` 已規範為唯一固定 AniBT Tracker，且 infohash 不變。詳見 [Tracker](/docs/tracker)。

### 安全

- **Tracker 白名單與邊緣保護**  
  固定 `/announce` 繼續只服務 AniBT 已收錄的 v1 `info_hash`；外部 hash 返回 not whitelisted。Cloudflare 保留 20-byte `info_hash`/`peer_id` 協議校驗與基礎 burst limit；公網 `/scrape`、`/api/*`、`/announce/v1/*` 與 UDP 繼續關閉。

## 2026 年 7 月 18 日

### 新增

- **全站 Markdown 內容協商**  
  公開 HTML 頁面支援 `Accept: text/markdown`，由 Cloudflare 在邊緣即時轉換；響應透過 `Vary: accept` 與 HTML 分離快取，並提供轉換前後 token 估算。JSON API、RSS/XML、圖片與 R2 物件保持原格式。目前公開內容信號為 `ai-train=yes, search=yes, ai-input=yes`。

### 修復

- **資源搜尋排序穩定性**  
  `/magnets` 與 `/rss/magnets.xml` 在文字搜尋同時按檔案大小或集數排序時，不再因 Typesense 最多 3 個排序欄位的限制導致搜尋失敗。明確排序、釋出時間與文字匹配優先級保持不變。

- **Latin 重音標題等價匹配**  
  純 Latin 標題同時保留原始重音與去變音符號的等價 token（例如 Caraméliser / Carameliser）；CJK 與混合腳本不折疊。若折疊產生多個番劇候選，matcher 保留全部候選並 fail closed，不會取第一名自動綁定。

- **Web 人工上傳匹配閉環**  
  Web torrent 上傳在字幕組成員鑑權後解析真實 `info.name` 並在服務端重放 v3，呼叫方不能偽造項目指紋。matcher 已自動命中同一番劇時不學習；人工選擇或不同自動目標第一次記為 pending，第二個不同集數啟用，同集不重複計數，衝突轉 suspended。matcher 不可用、內部異常或超長 `info.name` 不阻塞已校驗的明確選擇釋出，也不會學習 binding。

### 變更

- **公開 RSS 嚴格參數契約**  
  所有公開 RSS 的 `limit` 統一為單值 1..100（預設 100）；超大、重複、空、前導零或非整數不再靜默截斷。`q`/`search` 只允許一個值，並執行 NFKC、trim、空白折疊和 160 UTF-8 bytes 上限。規範化 URL 返回可快取一天的 308；非法輸入返回應用 400，生產邊緣可先返回 403。

### 最佳化

- **高基數搜尋 MISS 防護**  
  magnets/other 搜尋與空結果快取 600 秒，latest/filter 快取 120 秒；穩定查詢和快取 HIT 不消耗新查詢額度。新的高基數 MISS 使用 10 分鐘 / 24 小時 distinct-query 預算和全站併發 lease，超限返回 429 + Retry-After。Redis key 與結構化日誌只保存查詢 hash，不保存原始搜尋詞。

### 運維

- **索引器邊緣與源站硬化**  
  Jackett、Auto_Bangumi、ani-rss 的正常請求保持可用；Cloudflare 在邊緣攔截非法 limit，動態回源保護保持 500/10 秒，釋出失效改為精確 URL，不再清空全部搜尋變體。前置代理增加繞邊緣校驗、隱私安全採樣日誌與可靠輪轉。

### 資料

- **匹配索引 generation 2040**

## 2026 年 7 月 17 日

### 新增

- **釋出 API 組身份自檢**  
  `GET /api/releases/publish` 與 `GET /api/other-releases/publish` 支援 whoami：返回目前 API Key 綁定的 `groupId` / `groupName` / `groupSlug` / `apiKeySuffix`，不寫庫。正式釋出與 preview 成功響應也回顯同一組身份欄位，便於自動化在寫庫前發現 Key 綁錯字幕組。

  新增管理員別名提案佇列（`/admin/anime-alias-proposals`）。離線挖掘腳本從 `low_evidence` 等失敗樣本聚類拉丁縮寫 / 別名，提案需人工通過後才寫入 manual alias 並觸發投影同步；拒絕後不會再次復活同 anime + normalizedAlias 提案。執行期不自動降閾值、不自動入庫。

### 修復

- **禁止 0B magnet-only 正式入庫**  
  無 torrent 且 `fileSize` 無法解析為 >0（含缺少 magnet `xl=`）時，正式 publish 返回 422 / `reason=EMPTY_RELEASE_CONTENT`。preview 仍允許 0B，便於核對匹配與組身份。

### 最佳化

- **人工匹配同項目回溯**  
  字幕組 / 管理員對待匹配發布做人工綁定時，預設「記住項目」並「同時匹配同項目其他 pending」。一次確認會啟用該字幕組 + `projectFingerprint` 的 scoped binding，並把同組同指紋下最多 64 條 pending 一併匹配到所選番劇；不跨字幕組。

## 2026 年 7 月 16 日

### 新增

- **RSS 輸出 `anibt:bgmId`**  
  `/rss/magnets.xml`、`/rss/anime.xml`、`/rss/group/<slug>.xml` 的 anime 條目在 `xmlns:anibt` 下增加 `<anibt:bgmId>`（Bangumi subject id；已綁定才輸出）。`/rss/other/*` 不加。標準閱讀器可忽略該命名空間。

- **非番劇與合集安全退出**  
  獨立 PV/CM、MAD/AMV、遊戲影片、演唱會、真人劇、音樂專輯、舞台 / 朗讀劇、公告、桌布與字型包可返回 `non_anime`；單番劇單季合集仍可匹配，多番劇、真正多季和 S1+S2+OVA 合集返回 `unsupported`。

- **字幕組項目學習**  
  明確確認會按字幕組與項目指紋學習：第一次確認記錄 pending，第二個不同集數仍指向同一番劇後啟用，也可由 Web 人工選擇立即記住；衝突會暫停。自動 matcher 不反向訓練；active binding 仍必須通過候選投影、季度 / 年份 / 格式 / 集數 veto 與完整性檢查。

### 最佳化

- **種子匹配 v3 正式切流**  
  Canonical 介面 hard cut 為 `POST /api/animes/torrent-match`，GET 返回 JSON 405，不保留 v2 DTO、快取或相容層。服務端分別解析釋出標題與 torrent internal name，生成多語 AST，並讓 exact、strict recall、fuzzy recall 獨立檢索；新增 Season N - EP、括號版本年份、混合腳本和跨季連續集數判斷。任何 overflow、cutoff、hydrate 或 generation/projection 不一致都會禁止自動綁定。詳見 [種子匹配 API](/docs/open-api/anime-torrent-match)。

- **集數邊界與版本年收口**  
  新增 bracket 裸數字上下文判斷：`[Title][24][1080p]` 的 24 作為集數，`[Title][1080p][24][AAC]` 的 24 保持幀率；`2024年版` / `(2024)` 必須精確命中候選首播年。上季官方計數多含一個 SP 時，單集邊界和精確整季範圍只在 family 完整、後季排名第一、釋出時間與唯一目標共同成立時前移一集。

- **釋出流程統一 matcher**  
  釋出頁、批次釋出、人工匹配與 API Key 釋出統一使用服務端 v3 matcher。未傳番劇 ID 時釋出 API 直接執行同一決策；呼叫方偽造的內部自動匹配結果會被丟棄，只有 `decision.kind=auto` 才會直接綁定。

### 資料

- **乾淨匹配索引**

## 2026 年 7 月 11 日

### 文件

- **釋出成功與公開可見性**  
  文件明確：釋出 API 的 200 OK 表示站內寫入已接受並可靠交接後臺任務，**不等同於**該 release 已同步出現在 RSS、搜尋、公開頁面、CDN 或外站。呼叫方應使用返回的 `releaseId` 驗證目標正文；HTTP 200、`generatedAt`、ETag 或快取命中不能單獨作為內容已更新的證明。

### 最佳化

- **公開快照有序釋出**  
  magnets、公開 RSS、番劇 / 字幕組 / 資源詳情等公開快照改為不可變 R2 generation + PostgreSQL publication head。Web 只讀取並嚴格預熱 head 指向的同一 generation；Redis publication order / generation fence 會拒絕舊請求回寫，所有必要變體完成後才傳送 page-ready。更新或刪除番劇時繼續處理舊 / 新 BGM alias 與受影響 sitemap。

- **Edge 清快取可靠性**  
  CDN 清理改為持久化 URL 佇列與凍結 run/batch；token + generation lease 防止舊執行器誤確認，失敗可續跑，損壞狀態進入 quarantine 而不靜默丟棄。processed marker 保留 14 天；completed run 保留 14 天、quarantined run 保留 30 天。

### 運維

- **新鮮度運維門禁**  
  新增 snapshot queue/claim delay、publication pending/latency、head/watermark integrity、generation maintenance/GC 與 Edge D1 durable flush 指標、告警和預檢。queue age 高而 Redis warm latency 低時按排程 / backlog 排查，禁止透過延長 TTL 掩蓋傳播缺口。
