## Canonical configuration

```json title="Canonical OIDC configuration"
{
  "provider_id": "anibt",
  "protocol": "openid-connect",
  "issuer": "https://oauth.anibt.net",
  "discovery_url": "https://oauth.anibt.net/.well-known/openid-configuration",
  "authorization_endpoint": "https://oauth.anibt.net/oauth2/auth",
  "token_endpoint": "https://oauth.anibt.net/oauth2/token",
  "userinfo_endpoint": "https://oauth.anibt.net/userinfo",
  "jwks_uri": "https://oauth.anibt.net/.well-known/jwks.json",
  "end_session_endpoint": "https://oauth.anibt.net/oauth2/sessions/logout",
  "revocation_endpoint": "https://oauth.anibt.net/oauth2/revoke",
  "response_type": "code",
  "grant_type": "authorization_code",
  "pkce_method": "S256",
  "subject_type": "pairwise",
  "id_token_signing_alg": "RS256",
  "self_service_scopes": [
    "openid",
    "profile",
    "email",
    "offline_access"
  ],
  "web_bff_token_endpoint_auth_method": "client_secret_basic",
  "native_token_endpoint_auth_method": "none",
  "dynamic_client_registration": false
}
```

除 issuer 外，运行时优先从 discovery 获取端点与能力。上面的显式端点用于审查与故障排查，不代表可以跳过 discovery。

## 不可违反的实现约束

1. 仅使用 Authorization Code + PKCE S256；拒绝 implicit flow、password grant 与 `plain` PKCE。
2. Web / BFF secret 只能存在于服务端 secret manager；不得进入浏览器、移动包、公开变量、日志或仓库。
3. 原生应用是 public client，永远没有 secret。
4. 每次授权生成新的高熵 `state`、`nonce`、`code_verifier`，并一次性消费。
5. 回调先验证 `state`，再交换 code；ID Token 必须验证签名、`iss`、`aud`、`exp` 与 `nonce`。
6. 账号唯一键只能使用 pairwise `sub`；不得用 email、name 或 picture 自动合并账号。
7. claims 可能缺失；任何 `.anibt.local` 邮箱都不会返回。
8. `offline_access` 需要明确 consent；每次刷新后原子保存新的 refresh token，禁止并发复用旧 token。
9. redirect URI 与 post-logout URI 必须与 AniBT 中登记的字符串完全一致。
10. 不要尝试 Dynamic Client Registration、Hydra Admin API、operator 或任何未公开管理端点。
11. 不记录 authorization code、access token、refresh token、ID Token、Client secret、cookie、完整回调 URL 或 Authorization header。
12. 网络结果不明确时，不要盲目重复 code exchange、secret rotation 或 refresh token 请求。

## Client 类型选择

```text title="Client 类型选择"
如果应用有安全的服务端或 BFF：
  application_type = web_bff
  token_endpoint_auth_method = client_secret_basic
  redirect_uri = HTTPS
  secret = server-only

如果应用是桌面或移动原生应用：
  application_type = native
  token_endpoint_auth_method = none
  redirect_uri = claimed HTTPS 或 loopback HTTP
  secret = 不存在

如果应用是浏览器纯 SPA：
  不支持；增加 BFF 后按 web_bff 接入
```

复制下面内容，并补充你的框架、回调地址与会话存储方案：

```text title="AI 编程提示词"
权威文档：
- https://wiki.anibt.net/docs/oidc/integration
- https://wiki.anibt.net/docs/oidc/ai-reference

机器读取以上页面时发送请求头：Accept: text/markdown

固定合同：
- issuer: https://oauth.anibt.net
- flow: Authorization Code
- PKCE: S256，所有 Client 都必须使用
- state 和 nonce 每次随机生成、服务端保存、一次性验证
- Web/BFF 使用 client_secret_basic，secret 只能保存在服务端
- Native 使用 token_endpoint_auth_method=none，永远没有 secret

```

## 环境变量模板

变量名可按项目规范调整，但公开与私密边界必须保持：

```dotenv title="环境变量模板"
# 可公开配置
ANIBT_OIDC_ISSUER=https://oauth.anibt.net
ANIBT_OIDC_CLIENT_ID=从 AniBT 应用详情复制
ANIBT_OIDC_REDIRECT_URI=https://app.example.com/auth/anibt/callback
ANIBT_OIDC_POST_LOGOUT_REDIRECT_URI=https://app.example.com/signed-out

# 仅 Web / BFF 服务端；Native 不设置
ANIBT_OIDC_CLIENT_SECRET=从 AniBT 一次性页面复制到 secret manager
```

不要使用 `VITE_*`、`NEXT_PUBLIC_*`、`PUBLIC_*` 或其他会进入浏览器 bundle 的变量保存 Client secret。

## 最小实现顺序

1. 通过 discovery 初始化 OIDC client。
2. 创建 `/login/anibt`：生成并保存 `state`、`nonce`、PKCE verifier，然后重定向到 authorization endpoint。
3. 创建精确 callback route：验证 `state`，一次性取出 verifier 并交换 code。
4. 完整验证 ID Token，使用 `(issuer, sub)` 建立或查找外部账号绑定。
5. 只按已授权 scope 读取 claims；需要时调用 UserInfo。
6. 把业务会话与 provider token 分开保存，token 仅服务端可读。
7. 如申请 `offline_access`，实现原子 refresh rotation。
8. 实现 RP logout，验证 logout `state`。
9. 增加安全日志脱敏与协议测试。
