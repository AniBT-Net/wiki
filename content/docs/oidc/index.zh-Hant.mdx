AniBT 提供標準 OpenID Connect（OIDC）身份平台，第三方服務可讓使用者透過 AniBT 帳號登入。已登入使用者可在個人資料中建立和管理自己的 OAuth 應用程式；設定通過安全驗證後會立即開始自動配置，無需管理員審核。

<Callout type="info">
  Issuer：`https://oauth.anibt.net`<br />
  Discovery：[`https://oauth.anibt.net/.well-known/openid-configuration`](https://oauth.anibt.net/.well-known/openid-configuration)<br />
  應用程式管理：[AniBT 個人資料 → OAuth 應用程式](https://anibt.net/profile?tab=oauth-apps)
</Callout>

正式環境不開放 Dynamic Client Registration。Client 必須從 AniBT 個人資料建立；瀏覽器與業務伺服器均不能存取 Hydra Admin API 或 AniBT 內部 operator。

## 建立應用程式

<Steps>
  <Step>
    ### 開啟 OAuth 應用程式

    登入 AniBT 後，開啟個人資料中的「OAuth 應用程式」。
  </Step>
  <Step>
    ### 填寫必填項

    點選「新增 OAuth 應用程式」，在彈窗中填寫標示「必填」的項目。
  </Step>
  <Step>
    ### 等待自動配置

    提交後應用程式直接進入「設定中」，完成後顯示為「可用」。流程中沒有申請審核、approve 或 reject 狀態。
  </Step>
  <Step>
    ### 複製接入資訊

    開啟應用程式詳情，複製 Client ID、issuer、discovery、redirect URI 與授權範圍。
  </Step>
  <Step>
    ### 產生 Client secret（僅 Web / BFF）

    當應用程式類型為 Web / BFF 且狀態為「可用」後，再明確產生一次 Client secret。
  </Step>
</Steps>

一般使用者最多擁有 5 個未刪除應用程式。測試環境與正式環境必須建立為兩個獨立應用程式。

## 申請欄位

| 欄位 | 是否必填 | 用途 |
| --- | --- | --- |
| 應用程式名稱 | 必填 | 顯示在使用者授權頁 |
| 首頁網址 | 必填 | 應用程式公開 HTTPS 首頁，授權頁會提供連結 |
| 安全聯絡信箱 | 必填 | 安全通知與異常聯絡，不公開顯示 |
| 環境 | 必填 | 測試環境或正式環境；兩者必須分開 |
| 應用程式類型 | 必填 | Web / BFF 或原生應用程式 |
| 登入回呼網址 | 必填 | 登入完成後的精確 redirect URI，至少 1 個、最多 10 個 |
| 應用程式說明 | 選填 | 填寫後顯示在使用者授權頁 |
| 隱私權政策網址 | 選填 | 填寫後顯示在使用者授權頁，必須是完整 HTTPS 網址 |
| Logo 網址 | 選填 | 填寫後顯示在使用者授權頁，必須是完整 HTTPS 圖片網址 |
| 登出後回呼網址 | 選填 | RP logout 完成後的精確 redirect URI，最多 10 個 |

所有 URI 均按完整字串精確比對，不允許萬用字元、URL 使用者名稱密碼或 fragment。編輯應用程式時不能切換環境或應用程式類型；如需切換，請建立新應用程式。

## 應用程式類型

| 類型 | Client 驗證 | redirect URI | 適用情境 |
| --- | --- | --- | --- |
| Web / BFF | confidential，`client_secret_basic` | 僅 HTTPS | 有伺服器端或 BFF，可以安全儲存 secret |
| 原生應用程式 | public，`none` | HTTPS claimed redirect 或本機迴環 HTTP | 桌面或行動應用程式，永遠沒有 secret |

瀏覽器純 SPA 不受支援。網頁前端必須透過伺服器端 BFF 完成 code exchange 與 token 儲存。

## 自助授權範圍

| Scope | 資料與規則 |
| --- | --- |
| `openid` | 必需；返回按 Client sector 隔離的 pairwise `sub` |
| `profile` | 使用者公開名稱與頭像 |
| `email` | 需要使用者明確同意；僅返回可公開的真實信箱 |
| `offline_access` | 需要使用者明確同意；啟用 refresh token rotation 與 reuse protection |

`anibt:role` 和 `anibt:user_id` 不是自助授權範圍，只能由具有 `oidc_clients.manage` 權限的管理員設定。第三方應用程式不得用信箱自動合併帳號；任何 `.anibt.local` 合成信箱都不會進入 ID Token、UserInfo 或 access-token session。

## Client secret

原生應用程式永遠沒有 secret。Web / BFF 應用程式的 secret 規則如下：

- 建立應用程式時只使用不可交付的內部 bootstrap secret；
- 應用程式可用後，owner 必須明確點選產生或輪換；
- 操作要求最近重新驗證、CSRF 防護、限流和應用程式名稱確認；
- 新 secret 只在目前 HTTPS 回應中顯示一次；
- 目前為零重疊輪換，舊 secret 立即失效；
- 如果回應遺失，系統不會自動重試或再次顯示，只能再次明確輪換。

請立即把 secret 儲存到伺服器端 secret manager。不要放進瀏覽器套件、行動應用程式、公開倉庫、日誌、分析平台或 Wiki。

## 生命週期與安全操作

應用程式可能顯示「設定中」「可用」「更新中」「已停用」「刪除中」「錯誤」「已刪除」等技術狀態。owner 可以編輯設定、停用、恢復、撤銷全部授權、輪換 secret 或永久刪除應用程式。

如果應用程式或 owner 被停用、封禁或刪除，AniBT 會拒絕新的授權，並透過持久化背景任務停用 Client、撤銷相關 session。管理員可以直接處置濫用應用程式，但沒有 approve / reject 工作流程。
