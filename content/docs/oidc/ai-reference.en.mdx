```json
  "token_endpoint": "https://oauth.anibt.net/oauth2/token",
  "userinfo_endpoint": "https://oauth.anibt.net/userinfo",
  "jwks_uri": "https://oauth.anibt.net/.well-known/jwks.json",
  "end_session_endpoint": "https://oauth.anibt.net/oauth2/sessions/logout",
  "revocation_endpoint": "https://oauth.anibt.net/oauth2/revoke",
  "response_type": "code",
  "grant_type": "authorization_code",
  "pkce_method": "S256",
  "subject_type": "pairwise",
  "id_token_signing_alg": "RS256",
  "self_service_scopes": [
    "openid",
    "profile",

  ],
  "web_bff_token_endpoint_auth_method": "client_secret_basic",
  "native_token_endpoint_auth_method": "none",
  "dynamic_client_registration": false
}
```

At runtime, prefer discovery for endpoints and capabilities other than the fixed issuer. The explicit values above support review and troubleshooting; they do not justify skipping discovery.

## Non-negotiable implementation constraints

1. Use Authorization Code with PKCE S256 only. Reject implicit flow, password grant, and `plain` PKCE.
2. A Web / BFF secret exists only in a server-side secret manager; never in a browser, mobile bundle, public variable, log, or repository.
3. A native application is a public client and never has a secret.
4. Generate fresh high-entropy `state`, `nonce`, and `code_verifier` for every authorization and consume them once.
5. Validate `state` before exchanging the code. Validate ID Token signature, `iss`, `aud`, `exp`, and `nonce`.
6. Use pairwise `sub` as the only account key. Never merge accounts automatically by email, name, or picture.
7. Claims can be absent. Synthetic `.anibt.local` email is never returned.
8. `offline_access` requires explicit consent. Atomically store every rotated refresh token; never reuse an older token concurrently.
9. Redirect and post-logout URLs must exactly match the values registered in AniBT.
10. Do not attempt Dynamic Client Registration, Hydra Admin, the operator, or any unpublished management endpoint.
11. Do not log authorization codes, access tokens, refresh tokens, ID Tokens, Client secrets, cookies, full callback URLs, or Authorization headers.
12. Do not blindly repeat code exchange, secret rotation, or refresh requests after an ambiguous network result.

## Choose a client type

```text
If the application has a secure server or BFF:
  application_type = web_bff
  token_endpoint_auth_method = client_secret_basic
  redirect_uri = HTTPS
  secret = server-only

If it is a desktop or mobile native application:
  application_type = native
  token_endpoint_auth_method = none
  redirect_uri = claimed HTTPS or loopback HTTP
  secret = absent

If it is a browser-only SPA:
  unsupported; add a BFF and integrate as web_bff
```

## Prompt for an AI coding tool

Copy this prompt and add your framework, callback URL, and session-store details:

```text
Integrate AniBT OpenID Connect sign-in into this project.

Authoritative documentation:
- https://wiki.anibt.net/docs/oidc/integration
- https://wiki.anibt.net/docs/oidc/ai-reference

When reading these pages programmatically, send: Accept: text/markdown

Fixed contract:
- issuer: https://oauth.anibt.net
- flow: Authorization Code
- PKCE: S256 for every client
- generate state and nonce per request, store server-side, and validate once
- Web/BFF uses client_secret_basic; keep the secret server-side only
- Native uses token_endpoint_auth_method=none and never has a secret
- validate ID Token signature, iss, aud, exp, and nonce
- use pairwise sub as the only account key; never auto-merge by email
- treat claims as optional; .anibt.local email is never returned
- offline_access needs explicit consent and correct refresh rotation/reuse handling
- every redirect URL must match exactly
- logs must contain no code, token, secret, cookie, full callback URL, or Authorization header
- do not use Dynamic Client Registration, Hydra Admin, or AniBT's internal operator

First inspect the project's authentication and session boundaries and select a mature OIDC library. List required server-side environment variables, the exact callback URL, and logout URL. Implement sign-in, callback, ID Token validation, UserInfo, refresh, logout, and safe error handling. Add tests for state, nonce, PKCE, issuer, audience, code reuse, and refresh rotation. Never place the secret in a frontend variable.
```

## Environment variable template

Names may follow project conventions, but the public/private boundary is fixed:

```dotenv
# Public configuration
ANIBT_OIDC_ISSUER=https://oauth.anibt.net
ANIBT_OIDC_CLIENT_ID=copy from the AniBT application detail page
ANIBT_OIDC_REDIRECT_URI=https://app.example.com/auth/anibt/callback
ANIBT_OIDC_POST_LOGOUT_REDIRECT_URI=https://app.example.com/signed-out

# Web / BFF server only; omit for Native
ANIBT_OIDC_CLIENT_SECRET=copy once from AniBT into a secret manager
```

Never use `VITE_*`, `NEXT_PUBLIC_*`, `PUBLIC_*`, or another browser-exposed variable for the Client secret.

## Minimum implementation order

1. Initialize an OIDC client through discovery.
2. Add `/login/anibt`: generate and store `state`, `nonce`, and the PKCE verifier, then redirect to authorization.
3. Add the exact callback route: validate `state`, consume the verifier once, and exchange the code.
4. Fully validate the ID Token and bind the external account by `(issuer, sub)`.
5. Read only claims covered by granted scopes; call UserInfo when needed.
6. Store the application session separately from provider tokens; tokens remain server-readable only.
7. If using `offline_access`, implement atomic refresh-token rotation.
8. Implement RP logout and validate logout `state`.
9. Add protocol tests and sensitive-log redaction.
