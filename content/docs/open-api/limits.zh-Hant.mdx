為了保障公共服務的高可用性，防止爬蟲異常死循環或惡意刷流對站點造成衝擊，AniBT 在不同端點實施了透明的速率限制（Rate Limiting）與單次拉取筆數上限。

<Callout type="warn">
  **速率超限**：當請求頻次超過限制時，介面會回傳 `429 Too Many Requests`。回應標頭中會包含 `Retry-After: <秒數>`，客戶端腳本應擷取該狀態碼並等待指定秒數後再行重試，切勿在報錯後立即發起重試風暴。
</Callout>

## 分頁與 limit 參數規範

1. **`limit` 預設即最大**：公開 RSS 來源預設即輸出 100 筆記錄（系統支援的最大單頁量）。呼叫時**無需顯式傳入 `limit=100`**，直接省略該參數即可拉滿。
2. **合法參數範圍**：若需取得較少筆數（如最新 3 筆），可傳入 `1..100` 的整數。傳入非法格式或超出範圍的值將回傳 `400 Bad Request`。
3. **分頁游標（Cursor）**：主站資源列表及部分介面採用不透明的前進/後退游標（`cursor`）進行分頁。傳統的數字頁碼參數（`page`）已廢棄，建議全面適配游標機制。
4. **搜尋關鍵字長度**：搜尋介面的查詢詞（`q` / `search`）單次傳入最長不超過 160 個 UTF-8 位元組，且禁止包含控制字元。

## 友善呼叫規範

- **按需拉取**：對於固定字幕組或番劇，使用過濾條件精準訂閱，避免拉取全量全站數據。
- **避免併發**：不要針對同一端點 URL 併發發起多個輪詢請求。
- **輪詢間隔**：普通追番輪詢建議間隔 ≥ 5 分鐘，且務必配合 `If-None-Match` 條件請求。
