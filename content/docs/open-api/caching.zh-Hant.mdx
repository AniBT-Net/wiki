AniBT 的公開讀取介面與全站 RSS 訂閱全面支援 HTTP 條件請求（Conditional Requests）與協商快取機制。

<Callout type="info">
  **最佳實踐**：自建腳本或排程任務在輪詢 AniBT 時，請務必儲存上一次回應的 `ETag` 並在下次請求中透過 `If-None-Match` 攜帶。當無新番劇或新資源入庫時，伺服端將直接回傳 `304 Not Modified`（無正文），回應極快且不浪費下行頻寬。
</Callout>

## 輪詢頻率與建議規範

1. **合理輪詢間隔**：建議客戶端輪詢間隔 **不小於 5 分鐘**。動漫 BT 資源通常以小時或天為單位釋出，過密的高頻輪詢不僅毫無收益，還極易觸發系統 IP 速率限制。
2. **優先使用 `If-None-Match`**：AniBT 的快取標識基於精準的回應正文計算產生，因此請優先使用 `If-None-Match` 傳遞 ETag，避免單獨依賴可能受時區或傳輸影響的 `If-Modified-Since`。
3. **釋出後可見性**：釋出介面回傳 `200` 表示主記錄已成功受理入庫，通常在極短時間內即可反映在詳情頁與 RSS 中。建議透過回傳的 `releaseId` 核驗詳情，而非高頻重新整理首頁。

## 實戰：使用 curl 發送條件請求

```bash title="使用 If-None-Match 驗證 304 快取"
# 第一步：首次請求並擷取回應中的 ETag
RESPONSE_HEADERS=$(curl -sI "https://anibt.net/rss/anime.xml?bgmId=543360")
ETAG=$(echo "$RESPONSE_HEADERS" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')

echo "取得的 ETag: $ETAG"

# 第二步：攜帶 If-None-Match 發起後續輪詢
curl -sI -H "If-None-Match: $ETAG" \
  "https://anibt.net/rss/anime.xml?bgmId=543360"
```

- **預期回應**：若期間該番劇沒有新釋出的資源，伺服器將立即回傳 `HTTP/2 304`，且回應體長度為 0 位元組。
