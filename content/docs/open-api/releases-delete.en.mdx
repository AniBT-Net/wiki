---
title: Delete an anime release
description: DELETE /api/releases/{releaseId} — delete an anime release; GET …/deletion for status.
---

`rel_*` only. Requires `releases:delete`. No query, no body.

<ApiEndpoint method="DELETE" path="/api/releases/{releaseId}" auth="auth · releases:delete">
Waits up to ~2 seconds: 200 if done, else 202. Repeated DELETE is idempotent.
</ApiEndpoint>

<ApiEndpoint method="GET" path="/api/releases/{releaseId}/deletion" auth="auth · releases:delete">
Same deletion receipt. Unknown, never deleted, or unauthorized → 404.
</ApiEndpoint>

<Callout type="warn">
  `202` means accepted. Only `completed` means AniBT public surfaces are gone. It does not recall downloads, Tracker state, or external posts.
</Callout>

`releaseId`: `^rel_[A-Za-z0-9_-]+$`, 5–100 characters. Regular members delete only their own releases; owner / admin may delete any in the group. Unauthorized looks like missing (404). Keys cannot delete across groups. Keys created before scopes shipped have `releases:publish` only — check `scopes` via [`/me`](/docs/open-api/me).

Full fields: [API reference](/docs/open-api/reference).

```bash title="DELETE + poll"
release_id='rel_example'
base='https://anibt.net'

response=$(curl -sS -X DELETE \
  -H "Authorization: Bearer $ANIBT_API_KEY" \
  "$base/api/releases/$release_id")

while [ "$(jq -r '.result.state // .error.details.state // empty' <<<"$response")" = "pending" ]; do
  sleep 2
  response=$(curl -sS \
    -H "Authorization: Bearer $ANIBT_API_KEY" \
    "$base/api/releases/$release_id/deletion")
done

jq . <<<"$response"
```

| `state` | What to do |
| --- | --- |
| `pending` | Keep polling with `Retry-After` |
| `completed` | Stop |
| `failed` | Stop auto-retry; record `failure.code` and `X-Request-ID` |

`Retry-After` on `pending` is poll guidance. A real rate limit is `429`. Responses are `private, no-store` — do not cache receipts. A tombstoned `releaseId` cannot be reused. If the object is still referenced by another live release, `409` / `RELEASE_OBJECT_SHARED`.

| HTTP | What to do |
| --- | --- |
| 400 | Drop the body |
| 401 | Check Bearer / `X-API-Key` |
| 403 | Use a key with `releases:delete` |
| 404 | Missing or unauthorized; indistinguishable |
| 409 | Unlink the shared object first |
| 422 | Canonical `rel_*` path only; no query |
| 429 | Back off with `Retry-After` |
| 500 | DELETE observed terminal failure. Keep the receipt and `X-Request-ID`; stop blind retries |

`GET` of a failed operation still returns `200` with `state=failed`. A later `DELETE` maps that terminal failure to `500`.
