This document establishes global conventions, authentication protocols, and standard error handling when consuming the AniBT Open API.

<Callout type="warn">
  **Production Base URL**: `https://anibt.net`. Always use endpoints documented in the wiki and OpenAPI specification. Subtitle Group API Keys possess write and delete permissions; store them securely and never hardcode them into public repositories or client apps.
</Callout>

## Standard Error Response Schema

All write operations and non-2xx responses adhere to a unified JSON error structure:

```json title="Standard JSON Error Schema"
{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Torrent file is missing in multipart request",
    "reason": "TORRENT_REQUIRED",
    "retryable": false,
    "requestId": "req_01j7abc123456789"
  }
}
```

- **`code`**: Broad category of error (e.g., `BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`, `VALIDATION_ERROR`, `RATE_LIMITED`).
- **`reason`**: Machine-readable fine-grained error identifier (e.g., `EMPTY_RELEASE_CONTENT`, `TORRENT_REQUIRED`).
- **`retryable`**: Boolean indicating whether this error might succeed on a subsequent retry (e.g., `true` for rate limits, `false` for parameter errors).
- **`requestId`**: Unique distributed tracing identifier for the request, also returned in the `X-Request-ID` response header. Always provide this ID when reporting issues.
