Writes an anime release. Both live publish and preview require `releases:publish`.

<ApiEndpoint method="POST" path="/api/releases/publish" auth="auth · releases:publish">
Prefer multipart `.torrent` upload, or JSON with a magnet.
</ApiEndpoint>

<Callout type="warn">
  Do not put the key in clients, git, or issues. Inject it as a CI secret. `200` means the canonical row is written, not that RSS / search / pages already show it.
</Callout>

Full fields: [API reference](/docs/open-api/reference).

## Whoami

GET the same path. Does not write. Does not require publish scope. Assert `groupSlug` and `scopes` before a batch.

```bash title="whoami"
curl -X GET 'https://anibt.net/api/releases/publish' \
  -H 'Authorization: Bearer <YOUR_API_KEY>'
```

## Publish

<Tabs items={['multipart (recommended)', 'JSON']}>
  <Tab value="multipart (recommended)">
    ```bash title="Upload torrent"
    curl -X POST 'https://anibt.net/api/releases/publish' \
      -H 'Authorization: Bearer <YOUR_API_KEY>' \
      -F 'animeIdType=anilist' \
      -F 'animeId=170942' \
      -F 'title=[Group] Frieren - 01 [1080p].mkv' \
      -F 'episodeKey=01' \
      -F 'resolution=1080p' \
      -F 'language=CHS' -F 'language=JP' \
      -F 'subtitle=EXTERNAL' \
      -F 'format=MKV' \
      -F 'torrent=@/path/to/release.torrent'
    ```
  </Tab>
  <Tab value="JSON">
    ```bash title="JSON magnet"
    curl -X POST 'https://anibt.net/api/releases/publish' \
      -H 'Authorization: Bearer <YOUR_API_KEY>' \
      -H 'Content-Type: application/json' \
      --data @- <<'JSON'
    {
      "animeIdType": "mal",
      "animeId": "52991",
      "title": "[Group] Frieren - 01 [1080p].mkv",
      "magnetBase64": "magnet:?xt=urn:btih:...",
      "episodeKey": "01",
      "resolution": "1080p",
      "language": ["CHS", "JP"],
      "subtitle": "EXTERNAL",
      "format": "MKV",
      "fileSize": 734003200
    }
    JSON
    ```
  </Tab>
</Tabs>

## Constraints

- JSON requires `title`; multipart may fall back to the torrent internal name.
- Multipart requires `torrent`. JSON requires `magnetBase64` (raw magnet or Base64).
- Without a torrent, live publish needs `fileSize > 0`, else `422` / `EMPTY_RELEASE_CONTENT`.
- `notes`: Markdown + raw HTML, max 50000 characters, rendered as-is.
- `preview=true`: preview URL expires in 10 minutes and never enters public lists.
- With no anime ID, the server runs the same matcher. Do not send a forged match. Only `auto` binds immediately.
- If resolution and similar fields are omitted, defaults are `resolution=1080p`, `format=MKV`, `subtitle=INTERNAL`, `language=["CHS"]`, `version=v1`; final `format=MP4` leans to `EMBEDDED` subtitles.
- Same version already exists → `409`; change `version`.

## Nyaa proxy publishing

<Callout type="warn">
  Allowlisted groups only. Groups that publish supersampled releases cannot apply. Rules: [Nyaa proxy](/docs/nyaa-proxy). Must use multipart `.torrent`, and the torrent must contain `http://nyaa.tracker.wf:7777/announce`.
</Callout>

```bash title="AniBT + Nyaa"
curl -X POST 'https://anibt.net/api/releases/publish' \
  -H 'Authorization: Bearer <YOUR_API_KEY>' \
  -F 'torrent=@release.torrent' \
  -F 'title=[Group] Title - 01 [1080p][CHS]' \
  -F 'animeIdType=mal' \
  -F 'animeId=58514' \
  -F 'nyaa=true' \
  -F 'nyaaCategory=1_3'
```

Structured fields such as `sitePublish.nyaa.enabled` / `sitePublish.nyaa.category` also work. Sending Nyaa fields like `nyaaCategory` without `nyaa` still enables proxy publishing.

### Nyaa Proxy Fields and Categories

| Form field | JSON structured field | Required | Meaning |
| --- | --- | --- | --- |
| `nyaa` | `sitePublish.nyaa.enabled` | No | `true` requests proxy publishing |
| `nyaaCategory` | `sitePublish.nyaa.category` | Required when enabled | Code from the table. Chinese anime subs usually `1_3` |
| `nyaaComplete` | `sitePublish.nyaa.complete` | No | Complete flag. Default `false` |
| `nyaaRemake` | `sitePublish.nyaa.remake` | No | Remake flag. Default `false` |
| `nyaaDescription` | `sitePublish.nyaa.description` | No | Markdown sent to Nyaa, max 20000 characters. Falls back to `notes` with the same 20000 cap |
| `nyaaInformation` | `sitePublish.nyaa.information` | No | information, max 500 characters |

| Code | Nyaa category | Use when |
| --- | --- | --- |
| `1_1` | Anime - AMV | Anime music videos, edits, MAD/AMV |
| `1_2` | Anime - English-translated | English-translated anime |
| `1_3` | Anime - Non-English-translated | Non-English-translated anime. Simplified, traditional, or bilingual Chinese usually this |
| `1_4` | Anime - Raw | Anime RAW, no translation subs |
| `2_1` | Audio - Lossless | Lossless audio, e.g. FLAC, WAV |
| `2_2` | Audio - Lossy | Lossy audio, e.g. MP3, AAC, Opus |
| `3_1` | Literature - English-translated | English-translated manga, light novels, books |
| `3_2` | Literature - Non-English-translated | Non-English-translated manga, light novels, books. Chinese literature usually this |
| `3_3` | Literature - Raw | Untranslated manga, light novels, books |
| `4_1` | Live Action - English-translated | English-translated live action |
| `4_2` | Live Action - Idol/Promotional Video | Idol, promotional, or PV live action |
| `4_3` | Live Action - Non-English-translated | Non-English-translated live action |
| `4_4` | Live Action - Raw | Live action RAW |
| `5_1` | Pictures - Graphics | CG, artbooks, illustrations, scans |
| `5_2` | Pictures - Photos | Photo sets |
| `6_1` | Software - Applications | Applications |
| `6_2` | Software - Games | Games |

## Failures

| HTTP | What to do |
| --- | --- |
| 400 | Check `title` / anime ID / `.torrent` |
| 401 | Check Bearer / `X-API-Key`; rotate if revoked |
| 403 | Use a key with `releases:publish` |
| 409 | Change `version`; do not retry the same payload |
| 413 | Torrent too large |
| 422 | Validation failed, e.g. `EMPTY_RELEASE_CONTENT` |
| 429 / 503 | Back off with `Retry-After` |
