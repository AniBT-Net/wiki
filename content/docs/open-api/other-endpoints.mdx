主入口之外，AniBT 还提供四个常用端点：两个 RSS（短链 + 全站）、两个 JSON（季度 + 单番剧）。

本页的 RSS 端点都返回原生 RSS 2.0 XML。浏览器直开 RSS URL 时不加载站点自定义 XSL/CSS，会使用浏览器默认 XML 树展示；RSS 阅读器和 BT 客户端继续按标准字段消费。

## 字幕组短链 `/rss/group/<slug>.xml`

等价于 `/rss/anime.xml?groupSlug=<slug>` 但 URL 更短，便于贴 README / 论坛。

<Callout type="warn">
  路径必须以 `.xml` 结尾。支持单值 `limit=1..100`，**不支持** Tag 过滤；需要过滤请走 [RSS 主入口](/docs/open-api/rss-anime)。非法 limit 返回应用 400，生产边缘可能先返回 Cloudflare 403。
</Callout>

```txt title="示例"
https://anibt.net/rss/group/kirara-fantasia.xml
https://anibt.net/rss/group/pre-s.xml
https://anibt.net/rss/group/kitauji-sub.xml
https://anibt.net/rss/group/haruhana.xml
```

条目与 [RSS 主入口](/docs/open-api/rss-anime) 一样会输出 AniBT 扩展字段（含 `<anibt:bgmId>`，有绑定才出现）。

## 全站磁力 `/rss/magnets.xml`

适合"看看全站最近发了什么"。

```txt title="基本用法"
https://anibt.net/rss/magnets.xml
https://anibt.net/rss/magnets.xml?limit=100
https://anibt.net/rss/magnets.xml?q=葬送的芙莉莲
https://anibt.net/rss/magnets.xml?resolution=1080p&language=CHS
```

每个 anime `<item>` 含 `xmlns:anibt` 结构化元数据，其中 **`<anibt:bgmId>`** 为 Bangumi subject id（已绑定则输出）。与 `/rss/anime.xml`、`/rss/group/*.xml` 字段一致；`/rss/other/*` 无此字段。

<Callout type="info">
  无 `q` 的 latest/filter 变体缓存 **120 秒**；带 `q` 的搜索（包括空结果）缓存 **600 秒**；两者均为 `stale-while-revalidate=60s`。详见 [HTTP 缓存与 304](/docs/open-api/caching)。
</Callout>

<Callout type="warn">
  `q` 与 `search` 是别名，只能提供一个值。搜索词会做 NFKC、trim 与空白折叠，UTF-8 最多 160 bytes；重复、空、控制字符或超长输入返回 `400 + no-store`。仅改变原始 query 参数对顺序时直接返回同一规范 `200`；默认值、兼容别名或其它字节级规范化仍返回可缓存一天的 `308`。新的高基数 MISS 超出预算时返回 `429 + Retry-After`。
</Callout>

## 季度番剧 `/api/seasons/anime`

第三方追番站 / 看板 / 编辑器辅助使用。**返回当季已上架番剧 + 可选季度列表。**

### 请求

```txt title="多种调用方式"
GET https://anibt.net/api/seasons/anime
GET https://anibt.net/api/seasons/anime?season=2026春
GET https://anibt.net/api/seasons/anime?season=2026-SPRING   # 也接受英文形式
GET https://anibt.net/api/seasons/anime?bgmId=543360         # 精确返回单个番剧
GET https://anibt.net/api/seasons/anime?query=夏日口袋        # 按番剧标题搜索
GET https://anibt.net/api/seasons/anime?season=2026夏&query=Summer%20Pockets
```

### 缓存与限流

| 项目             | 值                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 速率限制         | **30 次 / 60 秒 / IP**（与 `/api/anime/groups` 共用窗口）                                |
| `Cache-Control`  | `public, max-age=0, s-maxage=600, stale-while-revalidate=86400, stale-if-error=86400`（**浏览器重新验证 + CDN 10 分钟新鲜 + 24h SWR/SIE**） |
| 条件请求         | `If-None-Match`（ETag 形如 `W/"sa-{year}-{SEASON}[-b{bgmId}]-{count}-{lastMs}-{urlHash}"`）、`If-Modified-Since` |

<Callout type="warn">
  当前响应正文包含请求时间 `ts`，但现有 ETag / Last-Modified 没有覆盖该字段。直接回源的两次请求可能在校验器相同时返回不同正文；下列 `304` 只展示当前条件请求行为，不能证明正文逐字节未变化。
</Callout>

```bash title="当前条件请求行为（已知限制）"
curl 'https://anibt.net/api/seasons/anime'
curl 'https://anibt.net/api/seasons/anime?season=2026春'
curl 'https://anibt.net/api/seasons/anime?bgmId=543360'
curl 'https://anibt.net/api/seasons/anime?query=夏日口袋'

ETAG=$(curl -sSI 'https://anibt.net/api/seasons/anime' | grep -i ^etag: | awk '{print $2}' | tr -d '\r')
curl -i 'https://anibt.net/api/seasons/anime' -H "If-None-Match: $ETAG"
# → 当前可能返回 HTTP/2 304；这不是正文逐字节相同的证明
```

## 单番剧字幕组 `/api/anime/groups`

> 「这部番都谁在做？」一个 `bgmId` 即可拿到全部正在发布的字幕组、最近更新时间，以及**最近 30 条发布**。

**专为给 `/rss/anime.xml` 拼 `groupSlug` 提供候选**，也方便客户端直接做"番剧详情页 / 资源列表"。

### 请求

```txt
GET https://anibt.net/api/anime/groups?bgmId=543360
```

<TypeTable
  type={{
    'bgmId': {
      description: 'Bangumi ID（正整数），例如 543360。',
      type: 'integer',
    },
  }}
/>

### 响应（节选）

```jsonc title="200 OK"
{
  "ok": true,
  "ts": 1776841967132,
  "data": {
    "bgmId": 543360,
    "animeId": "nh73r0ernee7s0afv9s82f763983gcz7",
    "title": { /* primary / chinese / romaji / english / japanese */ },
    "groups": [
      {
        "groupId": "org_aagmgM9i0ZyR",
        "slug": "kitauji-sub",
        "name": "北宇治字幕组",
        "status": "ACTIVE",
        "lastUpdatedAt": 1776624843260,
        "items": [
          {
            "releaseId": "rel_fItEHE7r1gR1",
            "title": "[北宇治字幕组] 上伊那牡丹，酒醉身姿似百合 [02][WebRip][HEVC_AAC][繁日內嵌]",
            "magnet": "magnet:?xt=urn:btih:282e2b…",
            "episodeKey": "2",
            "resolution": "1080p",
            "language": ["CHT", "JP"],
            "subtitle": "EMBEDDED",
            "publishedAt": 1776624843260
          }
          /* … 最多 30 条，按 publishedAt desc … */
        ]
      }
      /* … 其他字幕组 … */
    ],
    "total": 4
  }
}
```

### 字段

- `ts` 是每次实际渲染响应时写入的墙钟时间，不是数据版本；当前 ETag / Last-Modified 未覆盖它。
- `groups` 列表按 `lastUpdatedAt` 倒序（最近发过的排前面）。
- `items`：该字幕组对该番剧最近发布的资源，**最多 30 条**，按 `publishedAt` desc。可直接渲染"番剧 × 字幕组"维度的资源面板，避免单独拉 RSS。
  - `magnet` 可能为 `null`（仅有种子文件、未生成磁力时）。
  - `episodeKey` 是稳定的集数键（如 `"01"`、`"SP01"`），便于客户端排序 / 聚合。
  - `language`：`("CHS" | "CHT" | "JP" | "EN" | "KO" | "ES" | "PT" | "FR" | "DE" | "IT" | "RU" | "AR" | "HI" | "ID" | "MS" | "TH" | "VI" | "TL" | "TR" | "PL" | "UK")[]`。
  - `subtitle`：`"EMBEDDED" | "EXTERNAL" | "BUILT_IN" | "NONE"`（内嵌 / 外挂 / 内封 / 无）。
- `slug` 与 [`/api/subtitle-groups`](/docs/open-api/subtitle-groups) 完全一致，可直接喂给 `/rss/anime.xml?groupSlug=…`。
- 如果该 `bgmId` 未上架或被隐藏，返回 `404 ANIME_NOT_FOUND`。

### 典型用法 — 给追番器拼 RSS

```bash title="两步拼出 RSS"
# Step 1: 知道 bgmId，拉它的字幕组列表
curl -s 'https://anibt.net/api/anime/groups?bgmId=543360' \
  | jq -r '.data.groups[].slug'
# kitauji-sub
# kirara-fantasia
# pre-s
# haruhana

# Step 2: 拼 RSS（多个字幕组、CHS+1080p）
curl 'https://anibt.net/rss/anime.xml?bgmId=543360&groupSlug=kitauji-sub,kirara-fantasia,pre-s,haruhana&language=CHS&resolution=1080p&limit=50'
```

### 缓存与限流

| 项目             | 值                                                                              |
| ---------------- | ------------------------------------------------------------------------------- |
| 速率限制         | **30 次 / 60 秒 / IP**（与 `/api/seasons/anime` 共用窗口）                        |
| `Cache-Control`  | `public, max-age=0, s-maxage=300, stale-while-revalidate=3600, stale-if-error=3600`（**浏览器重新验证 + CDN 5 分钟新鲜 + 1h SWR/SIE**） |
| 条件请求         | `If-None-Match`（`W/"ag-{bgmId}-{count}-{lastMs}-{urlHash}"`）、`If-Modified-Since` |

<Callout type="warn">
  release 变化使 `count` / `lastUpdatedAt` 推进时，当前 ETag 通常也会推进；但请求时间 `ts` 不在校验器中。因此相同 ETag / Last-Modified 仍可能对应不同正文，`304` 不能作为正文逐字节未变的证明。轮询频率仍建议不要短于 5 分钟。
</Callout>
