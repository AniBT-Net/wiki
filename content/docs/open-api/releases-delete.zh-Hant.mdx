---
title: 刪除番劇釋出
description: DELETE /api/releases/{releaseId} —— 刪除番劇釋出；GET …/deletion 查狀態。
---

只支援 `rel_*`。要求 `releases:delete`。無 query、無請求體。

<ApiEndpoint method="DELETE" path="/api/releases/{releaseId}" auth="鑑權 · releases:delete">
最多等待約 2 秒：完成回傳 200，否則 202。重複 DELETE 冪等。
</ApiEndpoint>

<ApiEndpoint method="GET" path="/api/releases/{releaseId}/deletion" auth="鑑權 · releases:delete">
查詢同一刪除回執。未知、從未刪除或無權一律 404。
</ApiEndpoint>

<Callout type="warn">
  `202` 只表示已受理。只有 `completed` 才表示站內公開面已不可見。不召回已下載內容、Tracker 和外站帖子。
</Callout>

`releaseId`：`^rel_[A-Za-z0-9_-]+$`，5–100 字元。普通成員只能刪自己的釋出；owner / admin 可刪本組任意釋出。無權與不存在一樣回傳 404。Key 不能跨組刪除。scope 上線前的舊 Key 僅有 `releases:publish`，用 [`/me`](/docs/open-api/me) 檢查 `scopes`。

完整欄位見 [API 參考](/docs/open-api/reference)。

```bash title="DELETE + 輪詢"
release_id='rel_example'
base='https://anibt.net'

response=$(curl -sS -X DELETE \
  -H "Authorization: Bearer $ANIBT_API_KEY" \
  "$base/api/releases/$release_id")

while [ "$(jq -r '.result.state // .error.details.state // empty' <<<"$response")" = "pending" ]; do
  sleep 2
  response=$(curl -sS \
    -H "Authorization: Bearer $ANIBT_API_KEY" \
    "$base/api/releases/$release_id/deletion")
done

jq . <<<"$response"
```

| `state` | 做什麼 |
| --- | --- |
| `pending` | 按 `Retry-After` 繼續輪詢 |
| `completed` | 停止 |
| `failed` | 停止自動重試，記錄 `failure.code` 與 `X-Request-ID` |

`pending` 的 `Retry-After` 是輪詢建議。真正超限回傳 `429`。回應 `private, no-store`，不要快取回執。被 tombstone 覆蓋的 `releaseId` 不能複用。若物件仍被另一條 live release 引用，回傳 `409` / `RELEASE_OBJECT_SHARED`。

| HTTP | 處理 |
| --- | --- |
| 400 | 去掉請求體 |
| 401 | 檢查 Bearer / `X-API-Key` |
| 403 | 改用含 `releases:delete` 的 Key |
| 404 | 不存在，或無權；兩者不可區分 |
| 409 | 先解除共享物件引用 |
| 422 | 只傳規範 `rel_*` 路徑，不要加 query |
| 429 | 按 `Retry-After` 退避 |
| 500 | DELETE 觀察到終態失敗。儲存回執和 `X-Request-ID`，停止盲目重試 |

`GET` 讀取已失敗操作仍回傳 `200` 且 `state=failed`。再次 `DELETE` 終態失敗對應為 `500`。
