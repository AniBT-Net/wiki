---
title: Other release RSS
description: GET /rss/other/<category>.xml — separate RSS feeds for manga, music, RAW, and stage releases; not mixed into the main RSS.
---

`/rss/other/<category>.xml` exports dedicated RSS feeds for other release categories. The supported categories are `manga`, `music`, `raw`, and `stage`.

<Callout type="warn">
  Other releases are **not** mixed into `/rss/magnets.xml`, `/rss/anime.xml`, or anime detail RSS feeds. Subscribe to the category feeds on this page when you need them.
</Callout>

## URLs

```txt title="Category RSS"
https://anibt.net/rss/other/manga.xml
https://anibt.net/rss/other/music.xml
https://anibt.net/rss/other/raw.xml
https://anibt.net/rss/other/stage.xml
```

## Response

Returns native standard RSS 2.0 XML. Opening an RSS URL in a browser no longer loads AniBT custom XSL/CSS; the browser renders its default XML tree while RSS readers and BT clients keep consuming the standard fields.

## Cache and indexing

- Responses support `ETag` / `If-None-Match`; unchanged feeds return `304 Not Modified`.
- Latest/filter variants without `q` use `s-maxage=120`; searches with `q`, including empty results, use `s-maxage=600`; both use `stale-while-revalidate=60`.
- Category publish changes invalidate the latest Redis family first, then purge every CDN query variant for that category. Search Redis identities still keep their independent 600-second TTL, so this is not a real-time search SLA.
- Search cache identities contain only a SHA-256 of the normalized query. Repeated/empty/control-bearing q, q+search together, or more than 160 UTF-8 bytes return `400 + no-store`; canonical equivalents return a cacheable one-day `308`.
- Only a new search MISS that passes both CDN and Redis consumes distinct-query/global-concurrency admission. Rejection returns `429 + Retry-After`; stable queries and cache HITs are not charged.
- These RSS responses use a `noindex, follow` search engine policy so category feeds are not indexed.
