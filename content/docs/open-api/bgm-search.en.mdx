---
title: Bangumi search
description: GET /api/bgm/search — public Bangumi subject lookup. Supports Chinese, English, Japanese, and romaji keywords.
---

`/api/bgm/search` is a **public** endpoint with no auth required. Use it to map "the title a user typed" to a stable Bangumi.tv subject id (`bgmId`) before passing it to [`/rss/anime.xml`](/docs/open-api/rss-anime) or [`/api/releases/publish`](/docs/open-api/releases-publish).

<Callout type="info">
  Production is served by the main Web runtime against AniBT's local Typesense anime index. It no longer proxies Bangumi upstream through a Convex HTTP action. Results cover anime already indexed by AniBT; missing titles need site metadata sync first.
</Callout>

## Request

```txt title="URL"
GET https://anibt.net/api/bgm/search?q=<keyword>&limit=<n>
```

Any of Chinese, English, Japanese, or romaji works.

```bash title="curl"
curl -s -G 'https://anibt.net/api/bgm/search' \
  --data-urlencode 'q=葬送的芙莉莲' -d 'limit=3'
```

<TypeTable

## Practical: search → build an RSS URL

```bash title="One-liner"
BGM=$(curl -s -G 'https://anibt.net/api/bgm/search' \
  --data-urlencode 'q=Frieren' -d 'limit=1' \
  | jq -r '.data[0].bgmId')

echo "https://anibt.net/rss/anime.xml?bgmId=$BGM&resolution=1080p&language=CHS"
```

## Caching & rate limiting

| Item            | Value                                                              |
| --------------- | ------------------------------------------------------------------ |
| `Cache-Control` | `public, max-age=0, s-maxage=300, stale-while-revalidate=300, stale-if-error=300` |
| ETag            | Supports `If-None-Match`; unchanged responses return `304 Not Modified` |
| Rate limit      | 60 requests / 60 s / IP; see [Rate limits](/docs/open-api/limits) |

## Notes

<Callout type="info">
  Results are sorted by text relevance, popularity, and update time, **not** guaranteed popularity alone. For ambiguous titles (multiple seasons, identical names, etc.) raise `limit` and let the user pick.
</Callout>

<Callout type="warn">
  In production code, cache the resolved `bgmId` locally — don't query on every publish or RSS request.
</Callout>
