`/rss/anime.xml` is the most flexible subscription endpoint: combine `bgmId` + `groupSlug` + multiple tags (`resolution` / `language` / `format` / `subtitle` / `episode` / `episodeKey`) in any way to subscribe to a show, a group, or the whole site.

<Callout type="warn">
  At least one of `bgmId` or `groupSlug` is required. Requests with neither are rejected.
</Callout>

## URL

```txt title="URL"
GET https://anibt.net/rss/anime.xml?<query>
```

<Callout type="warn">
  A repeated, empty, zero-padded, non-integer, or greater-than-100 `limit` returns application `400 + no-store`; the production edge may block it first with Cloudflare `403`. Canonically equivalent forms such as `limit=100` return a cacheable one-day `308` to the canonical URL. Clients must follow permanent redirects.
</Callout>

Reordering otherwise byte-identical raw query pairs no longer redirects: the request returns the same canonical `200`, while `atom:link rel="self"`, ETag, and Last-Modified continue to use the stable canonical URL.

<Callout type="warn">
  The current public-RSS validator does not cover every XML byte, and each origin render writes a request-time `lastBuildDate`. The same ETag / Last-Modified can therefore identify different bodies, so `304` is not reliable proof that the feed is unchanged. A shape-valid but unresolved anime owner may also return an empty `200`, while an unknown `/rss/group/<slug>.xml` returns `404`.
</Callout>

## Two equivalent ways to repeat a parameter

```txt title="Standard repeated query (recommended)"
?resolution=1080p&resolution=720p
```

```txt title="Comma-separated (also accepted)"
?resolution=1080p,720p
```

## Response

Returns native **RSS 2.0 + BEP 36** XML. Opening an RSS URL in a browser no longer loads AniBT custom XSL/CSS; the browser renders its default XML tree while RSS readers and BT clients keep consuming the standard fields.

## Backend execution

`/rss/anime.xml` is generated by the main Web runtime, not by a Convex RSS query fallback. The Web layer resolves `bgmId` / `groupSlug` through the Typesense `rss_resolvers` collection, then queries the Typesense `releases` collection:

| Provided                | Execution path                              |
| ----------------------- | ------------------------------------------- |
| `bgmId` + `groupSlug`   | Typesense filter constrained by anime and group |
| `bgmId` only            | Typesense filter constrained by anime       |
| `groupSlug` only        | Typesense filter constrained by group       |

Resolution, language, format, subtitle type, and similar tags are pushed into Typesense filters where possible. Display fields such as `episode` / `episodeKey` are post-filtered in a small Web-runtime window. Entity RSS uses **900 seconds in Redis + 120 seconds at edge/CDN + 60 seconds stale-while-revalidate**. Publish events invalidate the matching Redis family first, then purge every CDN query variant for the same `bgmId` / `groupSlug`. TTL remains the fallback if the event path fails; the current ETag limitation is described in the warning above.

## Mikan parameter compatibility

Mikan-style parameters can switch host and keep working as-is:

<Tabs items={['Original Mikan link', 'Switch host only', 'Recommended']}>
  <Tab value="Original Mikan link">
    ```txt
    https://mikanani.me/RSS/Bangumi?bangumiId=3921&subgroupid=615
    ```
  </Tab>
  <Tab value="Switch host only">
    ```txt
    https://anibt.net/rss/anime.xml?bangumiId=3921&subgroupid=615
    ```
    `bangumiId` and `subgroupid` are accepted as compatibility aliases.
  </Tab>
  <Tab value="Recommended">
    ```txt
    https://anibt.net/rss/anime.xml?bgmId=3921&groupSlug=<slug>
    ```
    Use the canonical names in new code.
  </Tab>
</Tabs>
