title: RSS main entry
description: GET /rss/anime.xml — flexible anime RSS with bgmId, group slug, multi-tag filters, and Mikan-compatible aliases.
---

`/rss/anime.xml` is the most flexible subscription endpoint: combine `bgmId`, `groupSlug`, and tags (`resolution` / `language` / `format` / `subtitle` / `episode` / `episodeKey`) to follow one show, one group, or related site-wide releases. Search engines are told not to crawl `/rss/`; subscriptions themselves are unchanged.

## Preconditions

- No authentication.
- Provide **at least one** of `bgmId` or `groupSlug`; omitting both is rejected.

## URL

```txt title="URL"
GET https://anibt.net/rss/anime.xml?<query>
```

<Callout type="warn">
  Duplicate, empty, zero-padded, non-integer, or `>100` `limit` values return application `400 + no-store`; production edge may respond with Cloudflare `403` first. Default-equivalent forms such as `limit=100` `308` to the canonical URL (cacheable for one day). Clients should follow permanent redirects.
</Callout>

When only the original query-pair order changes and no parameter bytes differ, the response is the same canonical `200` without redirect; `atom:link rel="self"`, ETag, and cache identity still use the stable canonical URL. `Last-Modified` is currently omitted.

<Callout type="warn">
  Public RSS computes `W/"anibt-sha256-{...}"` ETags from final XML UTF-8 bytes and no longer writes request-time `lastBuildDate`. Matching ETag ⇒ identical body; a matching-ETag `304` means current feed bytes are unchanged. `Last-Modified` is omitted. A well-shaped but unresolvable anime owner may still return an empty `200`; unknown `/rss/group/<slug>.xml` still returns `404`.
</Callout>

## Two equivalent multi-value forms

```txt title="Repeated query (preferred)"
?resolution=1080p&resolution=720p
```

```txt title="Comma-separated (also supported)"
?resolution=1080p,720p
```

## Success response

Returns native **RSS 2.0 + BEP 36** XML. Opening the URL in a browser shows the default XML tree (no site XSL/CSS). Readers and BitTorrent clients consume standard fields.

## Backend execution

`/rss/anime.xml` is generated by the main-site Web runtime and does not fall back to Convex RSS queries. Web resolves `bgmId` / `groupSlug` via Typesense `rss_resolvers`, then queries the Typesense `releases` collection:

| Inputs | Execution |
| ------ | --------- |
| `bgmId` + `groupSlug` | Typesense filter on anime and group |
| `bgmId` only | Typesense filter on anime |
| `groupSlug` only | Typesense filter on group |

Resolution, language, format, and subtitle tags are pushed into Typesense when possible; display fields such as `episode` / `episodeKey` may use a small Web post-filter. Entity RSS uses **Redis 900 s + edge/CDN 120 s + 60 s stale-while-revalidate**. Publish events invalidate Redis families first, then purge every CDN query variant for the same entity by `bgmId` / `groupSlug`. When an anime resolves to two owners, both Redis families and CDN variants refresh as one publish result. TTL remains a fallback if the event path fails; ETag always comes from the final cached XML body.

Mikan-style parameters work after host swap:

  <Tab value="Host swap">

  </Tab>
  <Tab value="Preferred form">

  </Tab>
