---
title: Subtitle group catalogue
description: GET /api/subtitle-groups — public group list; cache name → slug before building RSS URLs.
---

`/api/subtitle-groups` returns **slug, display name, release count, and anime count** for every visible group. Integrations should call it once at startup, cache the response locally, then build RSS URLs.

## Preconditions

- No authentication.
- Prefer `Accept: application/json`.

<Callout type="info">
  The catalogue changes rarely, so most polls hit 304. With `If-None-Match`, bandwidth is negligible.
</Callout>

## Request

```http title="HTTP"
GET https://anibt.net/api/subtitle-groups
Accept: application/json
```

## 304 support

ETag looks like `W/"anibt-sha256-{64 lowercase hex}"` and is computed from the final JSON UTF-8 bytes. A matching `If-None-Match` returns 304. `Last-Modified` is currently omitted.

```bash title="Verify 304"
H=$(curl -sI "https://anibt.net/api/subtitle-groups")
ETAG=$(echo "$H" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')
curl -sI -H "If-None-Match: $ETAG" "https://anibt.net/api/subtitle-groups" | head -1
# → HTTP/2 304
```

## Practice: pick target groups with jq

```bash title="Pick four groups"
curl -s https://anibt.net/api/subtitle-groups \
  | jq '.data[] | select(.name | test("Kirara Fantasia|Prejudice-Studio|北宇治字幕组|拨雪寻春")) | {name, slug}'
```

Output:

```json title="Result"
{"name":"Kirara Fantasia","slug":"kirara-fantasia"}
{"name":"Prejudice-Studio","slug":"pre-s"}
{"name":"北宇治字幕组","slug":"kitauji-sub"}
{"name":"拨雪寻春","slug":"haruhana"}
```

## Caching & rate limits

| Item | Value |
| ---- | ----- |
| `Cache-Control` | `public, max-age=0, s-maxage=300, stale-while-revalidate=86400, stale-if-error=86400` |
| Rate limit | Shared 60-second window with RSS endpoints; see [Rate limits & caps](/docs/open-api/limits) |
| Conditional requests | `If-None-Match` supported; `Last-Modified` currently omitted |
