---
title: RSS 主入口
description: GET /rss/anime.xml —— 支援 bgmId、字幕組 slug 與多 Tag 任意組合的 RSS 主入口，相容 Mikan 連結。
---

`/rss/anime.xml` 是最靈活的訂閱端點：用 `bgmId` + `groupSlug` + 多個 Tag（`resolution` / `language` / `format` / `subtitle` / `episode` / `episodeKey`）任意組合，訂閱一個番劇、一個字幕組或全站相關釋出。搜尋引擎不會抓 `/rss/`；訂閱本身照常工作。

## 前置條件

- 無需鑑權。
- 必須提供 `bgmId` 或 `groupSlug` **至少之一**；兩者都不傳會被拒絕。

## URL

```txt title="URL"
GET https://anibt.net/rss/anime.xml?<query>
```

<Callout type="warn">

只調整原始 query 參數對順序、且未改變任何參數位元組時，不再跳轉：請求直接返回同一份規範 `200`，`atom:link rel="self"`、ETag 與快取身分仍使用穩定規範 URL；目前省略 `Last-Modified`。

<Callout type="warn">
  公開 RSS 從最終 XML UTF-8 bytes 計算 `W/"anibt-sha256-{...}"` ETag，並移除了請求時間 `lastBuildDate`。相同 ETag 綁定相同正文；匹配 ETag 的 `304` 表示目前 feed bytes 未變化。目前省略 `Last-Modified`。shape 合法但無法解析的 anime owner 仍可能返回空 `200`，而未知 `/rss/group/<slug>.xml` 仍返回 `404`。
</Callout>

## 重複參數兩種寫法等價

```txt title="標準重複 query（建議）"
?resolution=1080p&resolution=720p
```

```txt title="逗號分隔（也支援）"
?resolution=1080p,720p
```

## 成功回應

返回 **RSS 2.0 + BEP 36** 原生 XML。瀏覽器直開 RSS URL 時不載入站點自訂 XSL/CSS，使用瀏覽器預設 XML 樹展示；RSS 閱讀器和 BT 客戶端按標準欄位消費。

## 後端執行方式

`/rss/anime.xml` 在主站 Web runtime 產生，不再回源 Convex RSS query。Web 層使用 Typesense 的 `rss_resolvers` collection 解析 `bgmId` / `groupSlug`，再查詢 Typesense `releases` collection：

| 提供                    | 執行方式                         |
| ----------------------- | -------------------------------- |
| `bgmId` + `groupSlug`   | Typesense filter 精確約束番劇與字幕組 |
| 僅 `bgmId`              | Typesense filter 約束番劇          |
| 僅 `groupSlug`          | Typesense filter 約束字幕組        |

解析度、語言、格式、字幕方式等 Tag 儘量下推到 Typesense filter；`episode` / `episodeKey` 等展示欄位只在 Web runtime 做小視窗後過濾。實體 RSS 使用 **Redis 900 秒 + edge/CDN 120 秒 + 60 秒 stale-while-revalidate**。釋出事件會先失效對應 Redis 家族，再按 `bgmId` / `groupSlug` 清除同一實體的全部 CDN 參數變體；當一個 anime 同時解析出兩個 owner 時，兩組 Redis 家族與 CDN 變體作為同一個釋出結果一起重新整理，不會只更新其中一側。TTL 繼續作為事件鏈路失敗時的兜底，ETag 始終由快取後的最終 XML 正文決定。
