`/rss/anime.xml` 是最靈活的訂閱端點：用 `bgmId` + `groupSlug` + 多個 Tag（`resolution` / `language` / `format` / `subtitle` / `episode` / `episodeKey`）任意組合訂閱一個番劇 / 字幕組 / 全站釋出。

<Callout type="warn">
  必須給 `bgmId` 或 `groupSlug` **至少之一**。兩者都不傳會被拒絕。
</Callout>

## URL

```txt title="URL"
GET https://anibt.net/rss/anime.xml?<query>
```

```txt title="標準重複 query（推薦）"

```

```txt title="逗號分隔（也支援）"
?resolution=1080p,720p
```

## 響應

## 後端執行方式

`/rss/anime.xml` 在主站 Web runtime 生成，不再回源 Convex RSS query。Web 層使用 Typesense 的 `rss_resolvers` collection 解析 `bgmId` / `groupSlug`，再查詢 Typesense `releases` collection：

| 提供                    | 執行方式                         |
| ----------------------- | -------------------------------- |
| `bgmId` + `groupSlug`   | Typesense filter 精確約束番劇與字幕組 |
| 僅 `bgmId`              | Typesense filter 約束番劇          |
| 僅 `groupSlug`          | Typesense filter 約束字幕組        |

解析度、語言、格式、字幕方式等 Tag 盡量下推到 Typesense filter；`episode` / `episodeKey` 等展示欄位只在 Web runtime 做小視窗後過濾。Redis SSR cache 預設 **120 秒 TTL + 60 秒 stale-while-revalidate**，Cloudflare Worker 在釋出事件後會主動清理 Redis RSS cache 並 purge CDN，因此公開 RSS 的新鮮度上限目標是 5 分鐘內，正常路徑通常更快。
