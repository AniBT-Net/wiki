AniBT public RSS feeds and REST APIs are designed from the ground up for seamless integration with third-party downloaders and automated workflows.

<Callout type="info">
  **Subscription Tip**: Public RSS feeds return up to 100 items by default (the maximum batch supported by the server). You do not need to append `limit=100` to the feed URL.
</Callout>

## Automated Downloader Configuration

<Tabs items={['qBittorrent', 'Sonarr', 'FlexGet']}>
  <Tab value="qBittorrent">
    1. Open qBittorrent and switch to the **RSS** tab in the sidebar.
    2. Click **New subscription**, paste your AniBT RSS feed URL, and save.
    3. Click **RSS Downloader (Rules)** in the upper right, create a rule, and check your new feed.
    4. Set your client's default polling interval to **15 to 30 minutes**.
  </Tab>

  <Tab value="Sonarr">
    1. Navigate to **Settings** → **Indexers** → **Add** in Sonarr.
    2. Choose **Torznab**, set **URL** to `https://anibt.net/torznab`, keep **API Path** as `/api`, and select `5070` under **Anime Categories**. See [Torznab API](/en/docs/open-api/torznab) for the full steps.
    3. To follow only a fixed anime or group, you can instead choose **Torrent RSS Feed** and enter one of the RSS URLs above.
  </Tab>

  <Tab value="FlexGet">
    Add the AniBT RSS feed as an input task in your `config.yml`:

    ```yaml title="config.yml"
    tasks:
      anime_task:
        rss: https://anibt.net/rss/anime.xml?bgmId=543360&language=CHS
        all_series: yes
        download: ~/Downloads/Torrents/
    ```
  </Tab>
</Tabs>

## Production Script Snippets

### 1. Bash Conditional Polling with HTTP 304 Caching

Caches and sends the `ETag` to receive empty `304 Not Modified` responses when no new releases exist:

```bash title="conditional_rss_poll.sh"
#!/usr/bin/env bash
set -euo pipefail

FEED_URL="https://anibt.net/rss/anime.xml?bgmId=543360"
ETAG_FILE="/tmp/anibt_anime_543360.etag"

# Load previous ETag
ETAG=""
if [ -f "$ETAG_FILE" ]; then
  ETAG=$(cat "$ETAG_FILE")
fi

echo "Checking for new releases..."
if [ -n "$ETAG" ]; then
  RESPONSE=$(curl -sI -H "If-None-Match: $ETAG" "$FEED_URL")
else
  RESPONSE=$(curl -sI "$FEED_URL")
fi

HTTP_STATUS=$(echo "$RESPONSE" | grep -i '^http/' | awk '{print $2}')

if [ "$HTTP_STATUS" = "304" ]; then
  echo ">>> No new content (304 Not Modified). Skipping download."
elif [ "$HTTP_STATUS" = "200" ]; then
  echo ">>> New releases found! Saving new ETag..."
  NEW_ETAG=$(echo "$RESPONSE" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')
  echo "$NEW_ETAG" > "$ETAG_FILE"
  # Trigger downloader or notification hooks here
fi
```

### 2. Asynchronous Release Deletion with Polling Loop

Initiates release deletion via `DELETE` and polls the status endpoint until receiving `completed`:

```bash title="delete_and_wait.sh"
#!/usr/bin/env bash
set -euo pipefail

RELEASE_ID="rel_01j7example123"
API_KEY="YOUR_SUBTITLE_GROUP_API_KEY"
BASE_URL="https://anibt.net"

echo "Initiating asynchronous deletion for: $RELEASE_ID"
DELETE_RES=$(curl -sS -X DELETE \
  -H "Authorization: Bearer $API_KEY" \
  "$BASE_URL/api/releases/$RELEASE_ID")

STATE=$(echo "$DELETE_RES" | jq -r '.result.state // .error.details.state // "pending"')

# Poll deletion task state
while [ "$STATE" = "pending" ]; do
  echo "Deletion task processing in queue; retrying in 2 seconds..."
  sleep 2
  STATUS_RES=$(curl -sS \
    -H "Authorization: Bearer $API_KEY" \
    "$BASE_URL/api/releases/$RELEASE_ID/deletion")
  STATE=$(echo "$STATUS_RES" | jq -r '.result.state // "pending"')
done

if [ "$STATE" = "completed" ]; then
  echo ">>> Release successfully purged from database and edge caches!"
else
  echo ">>> Deletion ended with state: $STATE"
fi
```
