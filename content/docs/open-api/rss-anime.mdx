---
title: RSS 主入口
description: GET /rss/anime.xml —— 支持 bgmId、字幕组 slug 与多 Tag 任意组合的 RSS 主入口，兼容 Mikan 链接。
---

`/rss/anime.xml` 是最灵活的订阅端点：用 `bgmId` + `groupSlug` + 多个 Tag（`resolution` / `language` / `format` / `subtitle` / `episode` / `episodeKey`）任意组合订阅一个番剧 / 字幕组 / 全站发布。

<Callout type="info">
  必须给 `bgmId` 或 `groupSlug` **至少之一**。两者都不传会被拒绝。
</Callout>

## URL

```txt title="URL"
GET https://anibt.net/rss/anime.xml?<query>
```

<Callout type="warn">
  `limit` 重复、为空、含前导零、不是整数或大于 100 时，应用返回 `400 + no-store`；生产边缘可能先返回 Cloudflare `403`。`limit=100` 等与默认值等价的写法会 `308` 到规范 URL，跳转可缓存 1 天；客户端应跟随永久重定向。
</Callout>

只调整原始 query 参数对顺序、没有改变任何参数字节时，不再跳转：请求直接返回同一份规范 `200`，`atom:link rel="self"`、ETag 与缓存身份仍使用稳定规范 URL；当前省略 `Last-Modified`。

<Callout type="warn">
  公开 RSS 现在从最终 XML UTF-8 bytes 计算 `W/"anibt-sha256-{...}"` ETag，并移除了请求时间 `lastBuildDate`。相同 ETag 绑定相同正文；匹配 ETag 的 `304` 表示当前 feed bytes 未变化。当前省略 `Last-Modified`。shape 合法但无法解析的 anime owner 仍可能返回空 `200`，而未知 `/rss/group/<slug>.xml` 仍返回 `404`。
</Callout>

## 重复参数两种写法等价

```txt title="标准重复 query（推荐）"
?resolution=1080p&resolution=720p
```

```txt title="逗号分隔（也支持）"
?resolution=1080p,720p
```

## 响应

返回 **RSS 2.0 + BEP 36** 原生 XML。浏览器直开 RSS URL 时不加载站点自定义 XSL/CSS，会使用浏览器默认 XML 树展示；RSS 阅读器和 BT 客户端继续按标准字段消费。

## 后端执行方式

`/rss/anime.xml` 在主站 Web runtime 生成，不再回源 Convex RSS query。Web 层使用 Typesense 的 `rss_resolvers` collection 解析 `bgmId` / `groupSlug`，再查询 Typesense `releases` collection：

| 提供                    | 执行方式                         |
| ----------------------- | -------------------------------- |
| `bgmId` + `groupSlug`   | Typesense filter 精确约束番剧与字幕组 |
| 仅 `bgmId`              | Typesense filter 约束番剧          |
| 仅 `groupSlug`          | Typesense filter 约束字幕组        |

分辨率、语言、格式、字幕方式等 Tag 尽量下推到 Typesense filter；`episode` / `episodeKey` 等展示字段只在 Web runtime 做小窗口后过滤。实体 RSS 使用 **Redis 900 秒 + edge/CDN 120 秒 + 60 秒 stale-while-revalidate**。发布事件会先失效对应 Redis 家族，再按 `bgmId` / `groupSlug` 清除同一实体的全部 CDN 参数变体；当一个 anime 同时解析出两个 owner 时，两组 Redis 家族与 CDN 变体作为同一个发布结果一起刷新，不会只更新其中一侧。TTL 继续作为事件链路失败时的兜底，ETag 始终由缓存后的最终 XML 正文决定。
