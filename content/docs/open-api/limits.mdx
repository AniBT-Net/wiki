为了保障公共服务的高可用性，防止爬虫异常死循环或恶意刷流对站点造成冲击，AniBT 在不同端点实施了透明的速率限制（Rate Limiting）与单次拉取条数上限。

<Callout type="warn">
  **速率超限**：当请求频次超过限制时，接口会返回 `429 Too Many Requests`。响应头中会包含 `Retry-After: <秒数>`，客户端脚本应捕获该状态码并等待指定秒数后再行重试，切勿在报错后立即发起重试风暴。
</Callout>

## 分页与 limit 参数规范

1. **`limit` 默认即最大**：公开 RSS 源默认即输出 100 条记录（系统支持的最大单页量）。调用时**无需显式传入 `limit=100`**，直接省略该参数即可拉满。
2. **合法参数范围**：若需获取较少条数（如最新 3 条），可传入 `1..100` 的整数。传入非法格式或超出范围的值将返回 `400 Bad Request`。
3. **分页游标（Cursor）**：主站资源列表及部分接口采用不透明的前进/后退游标（`cursor`）进行分页。传统的数字页码参数（`page`）已废弃，建议全面适配游标机制。
4. **搜索关键词长度**：搜索接口的查询词（`q` / `search`）单次传入最长不超过 160 个 UTF-8 字节，且禁止包含控制字符。

## 友好调用规范

- **按需拉取**：对于固定字幕组或番剧，使用过滤条件精准订阅，避免拉取全量全站数据。
- **避免并发**：不要针对同一端点 URL 并发发起多个轮询请求。
- **轮询间隔**：普通追番轮询建议间隔 ≥ 5 分钟，且务必配合 `If-None-Match` 条件请求。
