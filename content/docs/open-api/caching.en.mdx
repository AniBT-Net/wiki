---
title: HTTP caching & 304
description: Public reads use If-None-Match. Unchanged bodies return 304. Poll interval ≥ 5 minutes.
---

Public RSS and JSON support conditional requests. Writes, deletes, `/me`, and personal subscriptions are not cached.

Successful public JSON responses use `max-age=0` in browsers so they revalidate;
the edge uses the endpoint's `s-maxage` and stale windows. `/api/anime/groups`
keeps its existing JSON, `ETag`, `HEAD`, and conditional `304` behavior. When the
public read model is temporarily unavailable, the response is `503
SEARCH_UNAVAILABLE` with `Retry-After` and `no-store`; failures are never written
to the shared cache.

RSS has two cache identities. A fixed RSS URL without `limit`, search, or filters
checks the current publication version on every request; an unchanged body may
still return `304`, and `no-store` prevents shared caches from retaining an old
body. RSS URLs with `limit`, filters, or search use bounded refresh policies.
RSS `<ttl>` is a client polling hint, not server push.

<Callout type="info">
  Send the last `ETag`. Unchanged → `304` with no body. Prefer `If-None-Match`. Do not rely on `If-Modified-Since`.
</Callout>

Poll interval ≥ 5 minutes. Faster polling has no benefit and often hits 429.

```bash title="If-None-Match"
H=$(curl -sI "https://anibt.net/rss/anime.xml?bgmId=543360")
ETAG=$(echo "$H" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')
curl -sI -H "If-None-Match: $ETAG" \
  "https://anibt.net/rss/anime.xml?bgmId=543360"
```

Publish `200` does not mean the item is already in RSS. Check the returned `releaseId` on the detail page or in the RSS body.
