AniBT public read endpoints and RSS feeds fully support standard HTTP conditional requests and negotiated caching.

<Callout type="info">
  **Best Practice**: When polling AniBT with scripts or background tasks, store the `ETag` from the previous response and provide it in subsequent requests via `If-None-Match`. If no new releases have been indexed, the server immediately returns `304 Not Modified` with an empty body, saving round-trip time and bandwidth.
</Callout>

## Polling Guidelines & Frequency

1. **Reasonable Polling Intervals**: We strongly recommend polling intervals **no shorter than 5 minutes**. Anime torrents are published over hours or days; aggressive sub-minute polling provides zero benefit while risking IP rate limits.
2. **Prioritize `If-None-Match`**: AniBT calculates ETags from the exact response body bytes. Rely on `If-None-Match` rather than `If-Modified-Since`.
3. **Visibility After Publishing**: A `200` response from the publish endpoint confirms acceptance into the catalog, propagating to detail pages and feeds shortly thereafter. Verify new releases using the returned `releaseId` rather than hammering feed endpoints.

## Example: Conditional Request with curl

```bash title="Verifying 304 Caching with If-None-Match"
# Step 1: Make initial request and extract ETag header
RESPONSE_HEADERS=$(curl -sI "https://anibt.net/rss/anime.xml?bgmId=543360")
ETAG=$(echo "$RESPONSE_HEADERS" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')

echo "Captured ETag: $ETAG"

# Step 2: Poll with If-None-Match header
curl -sI -H "If-None-Match: $ETAG" \
  "https://anibt.net/rss/anime.xml?bgmId=543360"
```

- **Expected Result**: If no new releases have occurred for that anime, the server returns `HTTP/2 304` with a 0-byte body.
