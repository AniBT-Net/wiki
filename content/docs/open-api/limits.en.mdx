To safeguard public service availability and prevent runaway crawlers or traffic spikes from degrading platform performance, AniBT implements transparent rate limits and page size ceilings across its endpoints.

<Callout type="warn">
  **Rate Limit Exceeded**: When request frequency exceeds allowed quotas, the server responds with `429 Too Many Requests`. The response header includes `Retry-After: <seconds>`. Client scripts must catch this status code and wait the specified seconds before retrying, rather than immediately re-requesting.
</Callout>

## Pagination & Limit Parameter Rules

1. **Default Limit is Maximum**: Public RSS feeds default to 100 items (the maximum supported single-page batch). You **do not need to supply `limit=100`**; simply omit the parameter.
2. **Valid Range**: When requesting smaller batches (e.g., latest 3 items), provide an integer between `1..100`. Out-of-bounds or non-numeric values return `400 Bad Request`.
3. **Cursor Pagination**: Resource feeds and certain APIs use opaque previous/next `cursor` tokens. Legacy numeric `page` parameters are discontinued; adapt your scripts to use cursors.
4. **Query Length**: The search term parameter (`q` / `search`) accepts up to 160 UTF-8 bytes and rejects control characters.

## Good Neighbor Best Practices

- **Filter Targeted Data**: When tracking a specific series or fansub group, use specific filter parameters rather than scraping the entire catalog.
- **Avoid Concurrency**: Do not issue concurrent requests for the exact same URL.
- **Sensible Polling**: Polling intervals of ≥ 5 minutes combined with `If-None-Match` conditional requests keep both client and server healthy.
