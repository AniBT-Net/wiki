---
title: Rate limits & caps
description: Per-endpoint limit and rate windows.
---

Numbers and status codes are the public contract. Over limit returns `429`; back off with `Retry-After`.

## Per endpoint

| Endpoint | `limit` default | `limit` cap | Rate limit (default) |
| --- | --- | --- | --- |
| `/rss/anime.xml` | **100** | **100** | 120 req / 60 s / IP |
| `/rss/group/<slug>.xml` | 100 | **100** | 120 req / 60 s / IP |
| `/rss/magnets.xml` | 100 | **100** | 120 req / 60 s / IP |
| `/rss/other/<category>.xml` | 100 | **100** | 120 req / 60 s / IP |
| `/api/bgm/search` | 5 | **25** | 60 req / 60 s / IP |
| `/api/animes/search` | 24 | **50** | 120 req / 60 s / IP |
| `/api/animes/torrent-match` | 10 | **50** | 180 req / 60 s / IP |
| `/api/anime/lookup` | — | — | 60 req / 60 s / IP |
| `/api/mikan/group-lookup` | — | — | 60 req / 60 s / IP |
| `/api/subtitle-groups` | — | full list | 60 req / 60 s / IP |
| `/api/seasons/anime` | — | — | 30 req / 60 s / IP |
| `/api/anime/groups` | — | — | 30 req / 60 s / IP |
| `DELETE /api/releases/{releaseId}` | — | — | 30 req / 60 s / API key |
| `GET /api/releases/{releaseId}/deletion` | — | — | 120 req / 60 s / API key |

Deletion also has a pre-auth abuse window. `Retry-After` on a `pending` receipt is poll guidance; a real rate limit is `429`.

<Callout type="warn">
  Public RSS `limit` accepts a single integer `1..100`. Invalid values return app `400`; production edge may return `403` first. Default is already 100 — do not send `limit=100` or you may get `308`.
</Callout>

On `/rss/magnets.xml` and `/rss/other/*`, `q` / `search` may be only one value, max 160 UTF-8 bytes. New-keyword search: 120 / 10 minutes and 1000 / 24 hours per subject; over limit returns `429`. Stable queries do not count.

Public search is capped at 100 pages. `/magnets?page=` over that redirects to page 100. `/api/animes/search` `cursor` must be `ts_page:<page>`.

Very tight filters may return fewer than `limit` items.

## Clients

- Omit `limit` for 100 items.
- Send `If-None-Match`.
- Interval ≥ 5 minutes.
- Do not fan out concurrent requests to the same URL.
- Do not poll more often than once a minute.
