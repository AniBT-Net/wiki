下列示例都基于 `bgmId=543360`（《上伊那牡丹，酒醉身姿似百合花般》），4 个字幕组的 slug 已通过 [`/api/subtitle-groups`](/docs/open-api/subtitle-groups) 校验：

```txt title="目标字幕组"
kirara-fantasia   Kirara Fantasia
pre-s             Prejudice-Studio
kitauji-sub       北宇治字幕组
haruhana          拨雪寻春
```

## 1. 单字幕组 + 番剧（最常用）

```txt title="一个 RSS = 一个组 × 一个番剧"
https://anibt.net/rss/anime.xml?bgmId=543360&groupSlug=kirara-fantasia
https://anibt.net/rss/anime.xml?bgmId=543360&groupSlug=pre-s
https://anibt.net/rss/anime.xml?bgmId=543360&groupSlug=kitauji-sub
https://anibt.net/rss/anime.xml?bgmId=543360&groupSlug=haruhana
```

## 8. 高吞吐场景（一次性拉满）

```txt
https://anibt.net/rss/anime.xml?groupSlug=kirara-fantasia&limit=100
```

<Callout type="info">
  所有公开 RSS 的 `limit` 上限都是 **100**。超过上限、重复、为空、含前导零或非整数时不会截断：应用返回 400，生产边缘可能先返回 Cloudflare 403。详见 [限流与上限](/docs/open-api/limits)。
</Callout>

## 9. 删除番剧发布并轮询完成

删除 Key 必须显式包含 `releases:delete`。`202 Accepted` 后按状态端点轮询，不要把“请求已接受”误判为“所有公开面已清理”。

```bash title="DELETE + 状态轮询"
release_id='rel_example'
base_url='https://anibt.net'

response=$(curl -sS -X DELETE \
  -H "Authorization: Bearer $ANIBT_API_KEY" \
  "$base_url/api/releases/$release_id")

while [ "$(jq -r '.result.state // .error.details.state // empty' <<<"$response")" = "pending" ]; do
  sleep 2
  response=$(curl -sS \
    -H "Authorization: Bearer $ANIBT_API_KEY" \
    "$base_url/api/releases/$release_id/deletion")
done

jq . <<<"$response"
```

终态为 `completed` 时才停止；若为 `failed`，保存 `operationId` 与 `X-Request-ID` 并停止盲目重试。完整字段、状态码和完成边界见 [删除番剧发布](/docs/open-api/releases-delete)。
