AniBT 的公开读取接口与全站 RSS 订阅全面支持 HTTP 条件请求（Conditional Requests）与协商缓存机制。

<Callout type="info">
  **最佳实践**：自建脚本或定时任务在轮询 AniBT 时，请务必保存上一次响应的 `ETag` 并在下次请求中通过 `If-None-Match` 携带。当无新番剧或新资源入库时，服务端将直接返回 `304 Not Modified`（无正文），响应极快且不浪费下行带宽。
</Callout>

## 轮询频率与建议规范

1. **合理轮询间隔**：建议客户端轮询间隔 **不小于 5 分钟**。动漫 BT 资源通常以小时或天为单位发布，过密的高频轮询不仅毫无收益，还极易触发系统 IP 速率限制。
2. **优先使用 `If-None-Match`**：AniBT 的缓存标识基于精准的响应正文计算生成，因此请优先使用 `If-None-Match` 传递 ETag，避免单独依赖可能受时区或传输影响的 `If-Modified-Since`。
3. **发布后可见性**：发布接口返回 `200` 表示主记录已成功受理入库，通常在极短时间内即可反映在详情页与 RSS 中。建议通过返回的 `releaseId` 核验详情，而非高频刷新首页。

## 实战：使用 curl 发送条件请求

```bash title="使用 If-None-Match 验证 304 缓存"
# 第一步：首次请求并提取响应中的 ETag
RESPONSE_HEADERS=$(curl -sI "https://anibt.net/rss/anime.xml?bgmId=543360")
ETAG=$(echo "$RESPONSE_HEADERS" | grep -i '^etag:' | cut -d' ' -f2- | tr -d '\r')

echo "获取到的 ETag: $ETAG"

# 第二步：携带 If-None-Match 发起后续轮询
curl -sI -H "If-None-Match: $ETAG" \
  "https://anibt.net/rss/anime.xml?bgmId=543360"
```

- **预期响应**：若期间该番剧没有新发布的资源，服务器将立即返回 `HTTP/2 304`，且响应体长度为 0 字节。
