AniBT 普通账号支持邮箱验证码注册、邮箱密码登录，以及登录页当前显示的第三方账号入口。

<Callout type="info">
  注册入口是 [anibt.net/auth/sign-up](https://anibt.net/auth/sign-up)，登录入口是 [anibt.net/auth/sign-in](https://anibt.net/auth/sign-in)。字幕组发布权限仍需在普通账号注册后单独[申请入驻](/docs/apply)。
</Callout>

## 邮箱验证码注册

<Steps>
  <Step>
    ### 获取验证码
    输入邮箱并完成人机验证。验证码为 6 位数字，10 分钟内有效；同一邮箱的重发受冷却时间和服务端限流保护。

    为避免泄露邮箱是否已经注册，提交已存在的邮箱也会返回相同的成功提示，但不会发送新的注册验证码。已有账号请改用登录或密码重置。
  </Step>
  <Step>
    ### 验证邮箱
    填写昵称、密码和验证码。密码格式会先检查，格式不合格时不会消费验证码；验证码一旦验证成功即为一次性使用，并建立已验证的登录会话。
  </Step>
  <Step>
    ### 完成密码登记
    验证邮箱后，AniBT 会在同一会话内登记密码。如果网络响应中断或密码登记暂时失败，请在原页面直接重试，不要重新使用已经消费的验证码。

    未过期的注册进度会保留在当前标签页。即使整页刷新，原浏览器仍可先恢复权威会话，再继续完成密码登记；完成前不要切换邮箱、无痕窗口、设备或标签页。
  </Step>
</Steps>

<Callout type="warn">
  验证码、CAPTCHA ticket 和 OAuth callback state 都是一次性的。不要分享链接、验证码或回调 URL；重复刷新第三方登录回调页可能会被安全校验拒绝。
</Callout>

## 登录与找回密码

<Tabs items={["邮箱密码", "第三方账号", "忘记密码"]}>
  <Tab value="邮箱密码">
    在登录页输入注册邮箱和密码，并完成人机验证。连续失败会受到限流保护。
  </Tab>
  <Tab value="第三方账号">
    登录页只显示当前生产环境已启用的 provider，例如 Bangumi、KUNGal 或其它社交账号。授权完成后会回到 `https://anibt.net/api/auth/*`；如果回调已被消费或中途失败，请返回登录页重新发起，不要反复刷新旧回调。
  </Tab>
  <Tab value="忘记密码">
    使用登录页的“忘记密码”入口。重置邮件由后台队列发送；短暂延迟不代表请求失败，请避免连续重复提交。
  </Tab>
</Tabs>

## 会话恢复时会看到什么

公开页面会保持可缓存，不把用户会话写进共享 HTML。页面回到前台或首次加载时，客户端再确认真实 token，因此用户菜单有三种状态：

<TypeTable
  type={{
    authenticated: {
      description: '真实 token 已确认，显示账号菜单并连接私有 Convex 数据。',
      type: '已登录',
    },
    restoring: {
      description: '浏览器提示可能存在 session，但 token 请求仍在进行或遇到临时网络/5xx；显示缓存头像或中性按钮，不显示可点击的“登录”。',
      type: '恢复中',
    },
    anonymous: {
      description: '服务端明确确认没有有效 session，才显示登录入口；受保护页面此时会跳转到登录页。',
      type: '未登录',
    },
  }}
/>

临时网络错误不会被当成退出登录。主动退出、session 明确失效或账号被撤销后，AniBT 会清理本地的非敏感恢复提示和用户菜单缓存。

## 账号关联与安全建议

- 第三方账号关联只信任站点明确启用的 provider；不要把第三方 token 或 Cookie 发给他人。
- `anibt_auth_hint` 和本地用户菜单缓存只用于减少界面闪烁，不是鉴权凭据。
- 私有数据和发布权限始终由服务端 session、角色和字幕组成员关系校验。
- 如果登录状态长期停在恢复中，请先检查网络，再重新打开登录页；仍无法恢复时联系 [support@anibt.net](mailto:support@anibt.net)。
