---
title: 使用 AniBT 登录第三方应用
description: 创建 OAuth 应用，并通过标准 OpenID Connect 使用 AniBT 账号登录。
---

AniBT 提供标准 OpenID Connect（OIDC）身份平台。登录用户可以在个人资料中自助创建和管理 OAuth 应用；合法提交会直接进入配置并自动生效，不需要管理员审核。

<Callout type="info">
  Issuer 是 `https://oauth.anibt.net`，discovery 地址是 [`https://oauth.anibt.net/.well-known/openid-configuration`](https://oauth.anibt.net/.well-known/openid-configuration)。生产环境不开放 Dynamic Client Registration；请从 [个人资料的 OAuth 应用页](https://anibt.net/profile?tab=oauth-apps) 创建 Client。
</Callout>

## 创建应用

1. 打开个人资料的“OAuth 应用”标签页，选择“创建 OAuth 应用”。
2. 填写应用名称、说明、主页、隐私政策、联系邮箱、环境、应用类型、精确 callback / post-logout URI 与 scopes。
3. 提交后应用会进入 `provisioning`，完成同步后变为 `active`。流程中没有 `pending`、approve 或 reject 状态。
4. 在详情页复制 Client ID、issuer、discovery、callback、scopes 与接入信息。

每个普通用户最多保留 5 个未删除应用。每个应用最多登记 10 个 redirect URI 和 10 个 post-logout URI；staging 与 production 必须创建为不同应用。

## 应用类型与 URI

| 类型 | 要求 |
| --- | --- |
| Web / BFF | confidential Client；服务端使用 `client_secret_basic`；callback 必须是 HTTPS；必须使用 Authorization Code + PKCE S256 |
| Native | public Client；永远没有 secret；必须使用 PKCE S256；首版仅接受 HTTPS claimed redirect 或 loopback HTTP |

浏览器纯 SPA 不受支持，请使用 BFF。所有 URI 都按完整字符串精确匹配，不允许 wildcard、URL credentials 或 fragment。

## Scope 与 claims

| Scope | 数据与规则 |
| --- | --- |
| `openid` | 必需；返回按 Client sector 隔离的 pairwise `sub` |
| `profile` | 昵称、头像与标准 profile claims |
| `email` | 需要用户明确同意；仅返回可公开的真实邮箱 |
| `offline_access` | 需要用户明确同意；返回启用 rotation / reuse protection 的 refresh token |

`anibt:role` 与 `anibt:user_id` 不是自助 scope，只能用于由 AniBT 管理员直接配置的受限第一方 Client。应用不得用邮箱自动关联账号；synthetic `.anibt.local` 邮箱永远不会进入 ID token、UserInfo 或 access-token session。

## Client secret

Native Client 永远没有 secret。Web / BFF Client 变为 `active` 后，owner 可以在应用详情页显式生成 secret：

- 操作需要最近重新认证、CSRF 防护、限流与应用名称确认；
- 新 secret 只在当前 HTTPS response 显示一次，不会进入页面 SSR、日志或应用记录；
- 当前轮换为零重叠，旧 secret 会立即失效；
- 如果响应丢失，AniBT 不会自动重试或再次显示明文，只能再次显式轮换。

请立即把 secret 保存到服务端 secret manager，禁止放入浏览器包、公开仓库或客户端日志。

## 接入流程

- 仅支持 Authorization Code + PKCE S256。Client 必须验证 `state`、`nonce`、PKCE、ID token 签名、issuer、audience 与过期时间。
- access token 当前为 opaque；authorization code 最长 5 分钟，access token 与 ID token 为 15 分钟，refresh token 最长 30 天。
- 首次授权、scope 扩大、`email` 或 `offline_access` 请求会显示应用资料、用途和数据范围，用户可以拒绝。
- RP-initiated logout 默认结束 Hydra / RP 会话，不会自动退出 AniBT 主站会话。

## 管理与撤销

owner 可以编辑资料、URI 和自助 scopes，也可以 suspend、resume、撤销既有 grants、轮换 secret 或永久删除应用。配置同步或漂移错误会在详情页显示安全错误码与可用的重试操作。

应用或 owner 被停用、封禁或删除时，AniBT 会拒绝新的授权并通过持久化任务停用 Client、撤销相关会话。管理员可以直接处理滥用应用，但不存在 approve / reject 工作流。
