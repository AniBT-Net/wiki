AniBT Wiki 与站点功能的变更记录；仅收录与文档直接相关、可核验的事实。

<Callout type="info">
  日期按北京时间（UTC+8）。较新的更新在前。同一天内按 **新增 / 修复 / 安全 / 优化 / 变更 / 文档 / 运维 / 数据** 分组。

## 2026 年 8 月 9 日

### 运维

- **边缘缓存与 RSS 通知执行面迁移到私网 Bun/SQLite**
  AniBT 已将缓存失效、CDN warming 与 RSS→Telegram 调度从旧 Cloudflare Worker/D1/Queues 迁移到 Dokploy 管理的单实例 Bun 服务。Convex 使用持久化 wake 重试，服务在返回 `202` 前写入 SQLite，并由互不阻塞的 intake/purge runner 恢复未完成工作。旧 Worker、D1、Queues/DLQs、Custom Domain 与专用 WAF 已退役。公开 RSS URL、XML 字段、TTL、ETag、304 语义和用户调用方式不变。

## 2026 年 8 月 8 日

### 变更

- **字幕组图床删除改为可查询的严格生命周期**
  删除请求现在返回 HTTP `202` 与稳定 operation，重复请求复用同一删除链路；图片会立即从站内活动读路径隐藏，界面区分处理中、完成和失败。`complete` 只在 AniBT R2 对象已验证不存在，且短链接页面与 `i.anibt.net` 直链在 AniBT 控制的 Cloudflare 缓存中完成收敛并返回 `404` / `410` 后出现。独立加速链接、浏览器缓存和第三方副本不在完成范围内。详见 [字幕组图床](/docs/image-host)。

### 修复

- **公开 RSS 刷新策略收口**
  同时解析出 `bgmId` 与 `groupSlug` 的 anime，两组 Redis 家族和 CDN 变体作为同一发布结果一起刷新，不再出现只更新一个 owner 的中间状态。字幕组创建、规范 slug 重命名与删除会收敛旧/新完整路径及其 `404` 负缓存；日常发布仍保持 owner 范围。other 的 `groupId`-only 过滤跟随 category 刷新，带 `q` / `search` 的全文搜索继续按 600 秒 TTL 独立管理。URL、XML 字段、TTL、ETag 与 304 合同不变。

## 2026 年 8 月 7 日

### 修复

- **自定义发布标题模板权限与默认状态**
  字幕组成员均可读取本组自定义发布标题模板；创建、修改、排序或删除仅限组 owner 与管理员。删除当前默认模板时，系统在同一事务中清除默认引用并写入审计记录，不保留指向已删除模板的配置。模板名称、内容长度与排序完整性统一在服务端校验。

## 2026 年 8 月 6 日

### 修复

- **公开 RSS 实体失效只认权威 owner**
  anime / group / other RSS 的 CDN membership 现在由 Web 在解析 canonical owner 后随最终响应附加，旧的 URL-derived Cloudflare Response Rules 已退出。other free-text search、anime 未解析 owner 的空 `200` 与 group 未知 owner 的 `404` 不再被虚假实体标签误清；dual-owner anime 仍可由 `bgmId` 或 `groupSlug` 任一真实 owner 精确刷新。URL、TTL、ETag 与 304 合同不变。

### 优化

- **公开 catalog API 分阶段进入 Cloudflare edge**
  `/api/anime/lookup`、`/api/mikan/group-lookup` 与 `/api/bgm/search` 在 sealed representation、容量和滥用保护门通过后逐端点加入共享 edge cache。成功响应与 BGM 权威空结果可 `MISS → HIT`，GET、HEAD 与 304 共用 ETag；重复参数、未找到/冲突、上游、限流和服务器错误继续 `no-store`，不会扩大整个 `/api/*` 的缓存范围。查询参数顺序不改变缓存身份，Cookie 也不会造成公开对象碎片化。

### 文档

- **公开 RSS / catalog exact-body 条件请求合同上线**
  anime / group / other / magnets RSS 与 7 个 catalog API 现在从最终 JSON/XML UTF-8 bytes 计算 opaque SHA-256 weak ETag；GET、HEAD 与匹配 `If-None-Match` 的 304 共享同一缓存 representation。公开 RSS 已移除请求时间 `lastBuildDate`；`/api/seasons/anime`、`/api/anime/groups` 的 `ts` 改为缓存 representation materialization time，并进入正文与 ETag。当前这些端点省略 `Last-Modified`。anime 未解析 owner 仍可能空 `200`，group 未知 owner 仍 `404`；本次没有扩大另外 3 个 API 的 Cloudflare edge eligibility。

## 2026 年 8 月 4 日

### 新增

- **个人资料 OAuth 应用自助管理**
  普通用户现在可在个人资料的响应式弹窗中直接创建和管理 OIDC OAuth 应用，无需管理员审核，也没有独立创建页面。支持 Web / BFF 与原生应用、精确回调地址、自助授权范围、一次性零重叠密钥轮换、停用 / 恢复、撤销授权与删除；Dynamic Client Registration 继续关闭。OIDC 文档已整理为独立模块，包含[概览与字段说明](/docs/oidc)、[第三方业务接入指南](/docs/oidc/integration)和[AI / Agent 接入参考](/docs/oidc/ai-reference)。

## 2026 年 8 月 3 日

### 新增

- **AniBT OpenID Connect 身份平台**  
  上线 `oauth.anibt.net` 标准 OIDC issuer，支持 Authorization Code + PKCE S256、pairwise `sub`、显式 scope 同意、opaque access token、refresh rotation / reuse protection 与 RP logout。Dynamic Client Registration 保持关闭；synthetic 邮箱不会对外释放，账号安全撤销会持久化清理 Hydra session。详见 [使用 AniBT 登录第三方应用](/docs/oidc)。

## 2026 年 7 月 30 日

### 安全

- **MediaInfo 纯文本安全迁移**  
  发布详情的 MediaInfo 统一为 UTF-8 纯文本：主站 GET/HEAD 返回 `text/plain` 与 nosniff，页面只按文本显示。生产 Agent 改用 `mediainfo --Output=Text`，并强制验证 qBittorrent TLS 证书；历史 `.html` 引用与对象已全部转为可读文本并完成零残留清理。

- **RSS 输出编码加固**  
  公开 RSS 的 Markdown 链接与图片 URL 继续使用独立属性编码和安全协议策略；该边界与发布详情页恢复原始 HTML 相互独立。

### 修复

- **发布说明原始 HTML 支持恢复**  
  番剧与其他类发布说明、详情和预览再次按 Markdown + 原始 HTML 渲染；`details`/`summary`、表格、图片、链接、`div`/`span`/`font` 与内联 style 等历史排版继续可用。页面不启用 sanitizer；编辑边界仍是字幕组成员、管理员及受控发布 API Key。

## 2026 年 7 月 25 日

### 修复

- **公开 RSS 参数顺序与 CDN 缓存一致**  
  仅原始 query 参数对顺序不同的 magnets、anime、group 与 other RSS 现在直接返回同一规范 200；self URL、ETag 与缓存身份保持稳定，当前公开 RSS 省略 Last-Modified。默认值、兼容别名、大小写 / 空白 / 编码差异仍返回 308；非法重复参数保持应用 400 + no-store，非法 limit 在生产边缘可先返回 Cloudflare 403。

### 安全

- **个人订阅 RSS 私有缓存合同**  
  `/rss/subscriptions.xml` 的成功、缺少或无效凭证、限流与服务端错误响应统一返回 `private, no-store` 和两层 CDN no-store；该私人 feed 不提供公开 ETag 或 If-None-Match 304 合同。

## 2026 年 7 月 24 日

### 优化

- **RSS 实体缓存即时失效**  
  番剧、字幕组与其他类公开 RSS 在发布事件完成 Redis 家族失效后，会按 `bgmId`、`groupSlug` 或 category 一次清除同实体全部 Cloudflare CDN 参数变体。接口 URL、TTL、ETag 与 304 合同不变；magnets 搜索及搜索 Redis 身份继续按原 TTL 管理。

## 2026 年 7 月 22 日

### 新增

- **番剧发布删除 API**  
  新增 `DELETE /api/releases/{releaseId}` 与 `GET /api/releases/{releaseId}/deletion`。V1 仅支持 `rel_*`；DELETE 不接受 query 或请求体，返回稳定 `rdel_*` 回执并以 200/202 表示 completed/pending。completed 仅在站内主记录、详情 / 种子、Typesense、magnets、公开 / 订阅 RSS、Redis、Cloudflare 和 AniBT R2 完成不可见性验证后出现。外站帖子、Tracker 与客户端已缓存内容不在召回范围内。详见 [删除发布](/docs/open-api/releases-delete)。

### 安全

- **字幕组 API Key scopes**  
  API Key 现在显式选择 `releases:publish` / `releases:delete`（至少一个）；旧 Key 安全迁移为仅 `releases:publish`。发布要求 `releases:publish`，删除及状态查询要求 `releases:delete`；`/api/subtitle-groups/me` 与 publish whoami 会返回 `apiKeyId`、`apiKeySuffix` 和 `scopes`。

- **认证安全与 OAuth 稳定性**  
  Better Auth 升级到 1.6.23；CAPTCHA ticket 改为精确路径匹配和原子一次性消费，注册 / 登录旁路继续关闭。KUNGal token exchange 使用标准 form-urlencoded；OTP、验证、重置与欢迎邮件进入可重试邮件队列，不再同步等待外部邮件 provider。

### 优化

- **账号注册与会话恢复**  
  邮箱注册改为「发送验证码 → 原子验证并建立 session → session 内登记密码」。密码格式错误不消费验证码；验证或密码登记遇响应丢失可幂等重试，未过期流程整页刷新后也能继续。公开页只在服务端明确确认无 session 后显示登录入口，临时网络 / 5xx 不再造成假登出。

## 2026 年 7 月 21 日

### 优化

- **图床批量上传、延迟与进度**  
  准备上传改为每批最多 5 张，只做一次成员校验和一次批量控制面事务；同批状态轮询合并为一次 GET 与一次 Convex query。R2 PUT 的 ETag 会随任务传给 worker，用 If-Match 单次条件读取取代 staging 读前 / 读后 HEAD。支持的浏览器会先预缩放明显可减小的超大静态 JPEG/PNG/WebP；动画、HEIC/HEIF 等仍由 worker 处理。单图限制仍为 10 MiB。

## 2026 年 7 月 20 日

### 优化

- **图床直传与隔离转码**  
  字幕组图床改为浏览器直传 staging R2；主站 Web 只负责鉴权、预签名、对象核对和状态查询，不再读取图片二进制或执行转码。shared Bun worker 为每张图启动短生命周期子进程，用原生 `Bun.Image` 直接写入 `Bun.S3File`。静态图损坏或转码失败会明确失败；动画与 SVG 继续保留原格式。详见 [字幕组图床](/docs/image-host)。

## 2026 年 7 月 19 日

### 修复

- **Tracker 固定入口恢复**  
  AniBT Tracker 已恢复固定 `https://tracker.anibt.net/announce`，不保留 signed 双轨。既有站内种子无需换地址或重新下载；magnet、RSS 与 canonical `.torrent` 已规范为唯一固定 AniBT Tracker，且 infohash 不变。详见 [Tracker](/docs/tracker)。

### 安全

- **Tracker 白名单与边缘保护**  
  固定 `/announce` 继续只服务 AniBT 已收录的 v1 `info_hash`；外部 hash 返回 not whitelisted。Cloudflare 保留 20-byte `info_hash`/`peer_id` 协议校验和基础 burst limit；公网 `/scrape`、`/api/*`、`/announce/v1/*` 与 UDP 继续关闭。

## 2026 年 7 月 18 日

### 新增

- **全站 Markdown 内容协商**  
  公开 HTML 页面支持 `Accept: text/markdown`，由 Cloudflare 在边缘实时转换；响应通过 `Vary: accept` 与 HTML 分离缓存，并提供转换前后 token 估算。JSON API、RSS/XML、图片与 R2 对象保持原格式。当前公开内容信号为 `ai-train=yes, search=yes, ai-input=yes`。

### 修复

- **资源搜索排序稳定性**  
  `/magnets` 与 `/rss/magnets.xml` 在文本搜索同时按文件大小或集数排序时，不再因 Typesense 最多 3 个排序字段的限制导致搜索失败。显式排序、发布时间与文本匹配优先级保持不变。

- **拉丁重音标题等价匹配**  
  纯 Latin 标题同时保留原始重音与去变音符号的等价 token（例如 Caraméliser / Carameliser）；CJK 与混合脚本不折叠。若折叠产生多个番剧候选，matcher 保留全部候选并 fail closed，不会取第一名自动绑定。

- **Web 人工上传匹配闭环**  
  Web torrent 上传在字幕组成员鉴权后解析真实 `info.name` 并在服务端重放 v3，调用方不能伪造项目指纹。matcher 已自动命中同一番剧时不学习；人工选择或不同自动目标第一次记为 pending，第二个不同集数激活，同集不重复计数，冲突转 suspended。matcher 不可用、内部异常或超长 `info.name` 不阻塞已校验的显式选择发布，也不会学习 binding。

### 变更

- **公开 RSS 严格参数合同**  
  所有公开 RSS 的 `limit` 统一为单值 1..100（默认 100）；超大、重复、空、前导零或非整数不再静默截断。`q`/`search` 只允许一个值，并执行 NFKC、trim、空白折叠和 160 UTF-8 bytes 上限。规范化 URL 返回可缓存一天的 308；非法输入返回应用 400，生产边缘可先返回 403。

### 优化

- **高基数搜索 MISS 防护**  
  magnets/other 搜索与空结果缓存 600 秒，latest/filter 缓存 120 秒；稳定查询和缓存 HIT 不消耗新查询额度。新的高基数 MISS 使用 10 分钟 / 24 小时 distinct-query 预算和全站并发 lease，超限返回 429 + Retry-After。Redis key 与结构化日志只保存查询 hash，不保存原始搜索词。

### 运维

- **索引器边缘与源站硬化**  
  Jackett、Auto_Bangumi、ani-rss 的正常请求保持可用；Cloudflare 在边缘拦截非法 limit，动态回源保护保持 500/10 秒，发布失效改为精确 URL，不再清空全部搜索变体。前置代理增加绕边缘校验、隐私安全采样日志与可靠轮转。

### 数据

- **匹配索引 generation 2040**  
  生产已切到 `match_v3_20260718_2040`：8,621 个候选番剧、223,792 条别名、168 个 scoped bindings。固定 34,083 条语料中 28,559 条自动匹配（83.7925%），2024–2026 子集为 9,084 / 9,807（92.6277%）；Carameliser 与 Caraméliser 线上均自动命中 BGM 617123。

## 2026 年 7 月 17 日

### 新增

- **发布 API 组身份自检**  
  `GET /api/releases/publish` 与 `GET /api/other-releases/publish` 支持 whoami：返回当前 API Key 绑定的 `groupId` / `groupName` / `groupSlug` / `apiKeySuffix`，不写库。正式发布与 preview 成功响应也回显同一组身份字段，便于自动化在写库前发现 Key 绑错字幕组。

- **官方缩写别名提案审批**  
  新增管理员别名提案队列（`/admin/anime-alias-proposals`）。离线挖掘脚本从 `low_evidence` 等失败样本聚类拉丁缩写 / 别名，提案需人工通过后才写入 manual alias 并触发投影同步；拒绝后不会再次复活同 anime + normalizedAlias 提案。运行时不自动降阈值、不自动入库。

### 修复

- **禁止 0B magnet-only 正式入库**  
  无 torrent 且 `fileSize` 无法解析为 >0（含缺少 magnet `xl=`）时，正式 publish 返回 422 / `reason=EMPTY_RELEASE_CONTENT`。preview 仍允许 0B，便于核对匹配与组身份。

### 优化

- **人工匹配同项目回溯**  
  字幕组 / 管理员对待匹配发布做人工绑定时，默认「记住项目」并「同时匹配同项目其他 pending」。一次确认会激活该字幕组 + `projectFingerprint` 的 scoped binding，并把同组同指纹下最多 64 条 pending 一并匹配到所选番剧；不跨字幕组。

## 2026 年 7 月 16 日

### 新增

- **RSS 输出 `anibt:bgmId`**  
  `/rss/magnets.xml`、`/rss/anime.xml`、`/rss/group/<slug>.xml` 的 anime 条目在 `xmlns:anibt` 下增加 `<anibt:bgmId>`（Bangumi subject id；已绑定才输出）。`/rss/other/*` 不加。标准阅读器可忽略该命名空间。

- **非番剧与合集安全退出**  
  独立 PV/CM、MAD/AMV、游戏视频、演唱会、真人剧、音乐专辑、舞台 / 朗读剧、公告、壁纸与字体包可返回 `non_anime`；单番剧单季合集仍可匹配，多番剧、真正多季和 S1+S2+OVA 合集返回 `unsupported`。

- **字幕组项目学习**  
  显式确认会按字幕组与项目指纹学习：第一次确认记录 pending，第二个不同集数仍指向同一番剧后激活，也可由 Web 人工选择立即记住；冲突会暂停。自动 matcher 不反向训练；active binding 仍必须通过候选投影、季度 / 年份 / 格式 / 集数 veto 与完整性检查。

### 优化

- **种子匹配 v3 正式切流**  
  Canonical 接口 hard cut 为 `POST /api/animes/torrent-match`，GET 返回 JSON 405，不保留 v2 DTO、缓存或兼容层。服务端分别解析发布标题与 torrent internal name，生成多语言 AST，并让 exact、strict recall、fuzzy recall 独立检索；新增 Season N - EP、括号版本年份、混合脚本和跨季连续集数判断。任何 overflow、cutoff、hydrate 或 generation/projection 不一致都会禁止自动绑定。详见 [种子匹配 API](/docs/open-api/anime-torrent-match)。

- **集数边界与版本年收口**  
  新增 bracket 裸数字上下文判断：`[Title][24][1080p]` 的 24 作为集数，`[Title][1080p][24][AAC]` 的 24 保持帧率；`2024年版` / `(2024)` 必须精确命中候选首播年。上季官方计数多含一个 SP 时，单集边界和精确整季范围只在 family 完整、后季排名第一、发布时间与唯一目标共同成立时前移一集。

- **发布流程统一 matcher**  
  发布页、批量发布、人工匹配和 API Key 发布统一使用服务端 v3 matcher。未传番剧 ID 时发布 API 直接执行同一决策；调用方伪造的内部自动匹配结果会被丢弃，只有 `decision.kind=auto` 才会直接绑定。

### 数据

- **干净匹配索引**  
  生产 matcher 已切到 `match_v3_20260716_2112`，共 8,621 个候选番剧、223,778 条别名和 24 个 scoped bindings；34,083 条固定语料中，2024–2026 番剧自动匹配为 9,091 / 9,781（92.9455%），排除后续单独处理合集的 VCB 后为 8,744 / 9,339（93.6289%）。TMDB/TVDB 不参与匹配。

## 2026 年 7 月 14 日

### 新增

- **可解释的自动绑定契约**  
  匹配响应新增 `decisionReason`、`exactAnimeCount`、`vetoCategory` 和有界 `evidenceSummary`。调用方只有在 `shouldAutoSelect=true` 时才能自动采用 `bestMatch`；共享标题、结构冲突、弱证据或 exact overflow 会保留人工确认。

### 优化

- **种子标题番剧匹配**  
  `/api/animes/torrent-match` 改用独立 `anime_match_aliases` 索引，综合中文、繁中、日文、罗马字、英文、多语言标题列表，以及 Season/Cour/Part/Sequence/Format 证据进行全局消歧；不再用旧 `allTitles` 文本分差授权自动绑定。长多语言 exact 查询改用请求体发送，不再受 Typesense GET 查询串 4000 字符限制。

- **匹配缓存安全**  
  旧 GET 匹配接口曾使用 60 秒共享缓存并禁用 stale fallback；7 月 16 日 POST v3 hard cut 后，该 GET 接口、v2 DTO 与缓存均已删除，当前匹配响应固定 no-store。

## 2026 年 7 月 12 日

### 优化

- **发布与上传错误契约**  
  番剧与其他类资源发布 API 的 JSON 磁力和 multipart 种子上传失败统一返回 `ok=false` 的错误 envelope，包含机器码 `code`、安全提示 `message`、可选业务 `reason`、`retryable`、`retryAfterMs`、`requestId` 和 i18n 元数据；`X-Request-ID` 可用于关联服务端日志。

- **可操作的发布状态码**  
  计划部署期间暂停发布交接改为 503 Service Unavailable，并返回 `Retry-After`、`reason=DEPLOYMENT_IN_PROGRESS`；重复发布版本保留 409 与 `reason=RELEASE_VERSION_EXISTS`；写入限流返回 429、`reason=RATE_LIMITED` 和退避时间。

## 2026 年 7 月 11 日

### 文档

- **发布成功与公开可见性**  
  文档明确：发布 API 的 200 OK 表示站内写入已接受并可靠交接后台任务，**不等同于**该 release 已同步出现在 RSS、搜索、公开页面、CDN 或外站。调用方应使用返回的 `releaseId` 验证目标正文；HTTP 200、`generatedAt`、ETag 或缓存命中不能单独作为内容已更新的证明。

### 优化

- **公开快照有序发布**  
  magnets、公共 RSS、番剧 / 字幕组 / 资源详情等公开快照改为不可变 R2 generation + PostgreSQL publication head。Web 只读取并严格预热 head 指向的同一 generation；Redis publication order / generation fence 会拒绝旧请求回写，所有必要变体完成后才发送 page-ready。更新或删除番剧时继续处理旧 / 新 BGM alias 与受影响 sitemap。

- **Edge 清缓存可靠性**  
  CDN 清理改为持久化 URL 队列与冻结 run/batch；token + generation lease 防止旧执行器误确认，失败可续跑，损坏状态进入 quarantine 而不静默丢弃。processed marker 保留 14 天；completed run 保留 14 天、quarantined run 保留 30 天。

### 运维

- **新鲜度运维门禁**  
  新增 snapshot queue/claim delay、publication pending/latency、head/watermark integrity、generation maintenance/GC 与 Edge D1 durable flush 指标、告警和预检。queue age 高而 Redis warm latency 低时按调度 / backlog 排查，禁止通过延长 TTL 掩盖传播缺口。
