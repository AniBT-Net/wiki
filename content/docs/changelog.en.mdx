Changelog for AniBT Wiki and site features that the docs cover. Entries are factual and verifiable only.

<Callout type="info">
  Dates use Beijing time (UTC+8). Newer updates appear first. Entries on the same day are grouped by **Added / Fixed / Security / Improved / Changed / Docs / Operations / Data**.
</Callout>

## August 13, 2026

### Fixed

- **Public weekly timetable now uses real daily air times**
  The `/` and `/seasonal` timetable now renders actual events from the bgm.wiki 7-day window. One title can appear on more than one date, with official times and episode numbers, instead of projecting last week’s slot by `+7` days. If a title is gone from a day that still has other events, it is removed that day. If a whole day arrives with zero events, the previous day is kept so a truncated fetch cannot wipe Monday–Wednesday.

## August 11, 2026

### Fixed

- **RSS publication timestamps standardized on Asia/Shanghai**
  Standard `<pubDate>` values in public anime, group, magnets, and other feeds plus personal subscription RSS now use RFC 822 with the explicit Asia/Shanghai offset `+0800`. The `<pubDate>` nested in torrent metadata uses RFC 3339 with `+08:00`. RSS URLs, TTLs, ETags, and 304 semantics are unchanged.

## August 9, 2026

### Operations

- **Edge cache and RSS notification execution moved to private Bun/SQLite**
  AniBT moved cache invalidation, CDN warming, and RSS-to-Telegram scheduling from the former Cloudflare Worker/D1/Queues stack to a single Dokploy-managed Bun service. Convex now owns durable wake retries; the service commits each wake to SQLite before returning `202`, and isolated intake/purge runners recover unfinished work. The former Worker, D1 database, Queues/DLQs, Custom Domain, and dedicated WAF rule have been retired. Public RSS URLs, XML fields, TTLs, ETags, 304 semantics, and client usage are unchanged.

## August 8, 2026

### Changed

- **Subtitle-group image deletion now has a queryable strict lifecycle**
  Deletion requests now return HTTP `202` with a stable operation, and repeated requests reuse the same deletion chain. The image is immediately hidden from active site reads while the UI distinguishes pending, complete, and failed states. `complete` appears only after the AniBT R2 object is verified absent and the short page plus `i.anibt.net` direct URL converge in AniBT-controlled Cloudflare caches and return `404` / `410`. Separate accelerated links, browser caches, and third-party copies are outside this completion scope. See [Image host](/docs/image-host).

### Fixed

- **Public RSS refresh policy closed**
  Anime resolved to both `bgmId` and `groupSlug` refreshes both Redis families and CDN variant sets as one publication result, so clients never observe a one-owner-only intermediate. Group creation, canonical-slug rename, and deletion converge old/new full paths and cached `404` state; routine publication stays owner-scoped. Other `groupId`-only filters follow category freshness; free-text `q` / `search` remains independently TTL-owned for 600 seconds. URLs, XML fields, TTLs, ETags, and 304 semantics are unchanged.

## August 7, 2026

### Fixed

- **Custom release-title template permissions and default state**
  All group members can read custom release-title templates; create, edit, reorder, and delete stay limited to the group owner and administrators. Deleting the active default clears its reference and writes the audit event in the same transaction, so config cannot point at a removed template. Name/content length and reorder completeness are validated server-side.

## August 6, 2026

### Fixed

- **Public RSS entity invalidation now requires an authoritative owner**
  CDN membership for anime / group / other RSS is now attached by Web only after resolving the canonical owner, and the old URL-derived Cloudflare Response Rules have been retired. Other free-text search, unresolved-anime empty `200`, and unknown-group `404` responses no longer receive false entity tags; a dual-owner anime still refreshes through either its real `bgmId` or `groupSlug`. URLs, TTLs, ETags, and 304 semantics are unchanged.

### Improved

- **Public catalog APIs are admitted to the Cloudflare edge in stages**
  `/api/anime/lookup`, `/api/mikan/group-lookup`, and `/api/bgm/search` joined shared edge caching one endpoint at a time after the sealed-representation, capacity, and abuse-protection gates passed. Successful responses and BGM's authoritative empty result can go `MISS → HIT`, while GET, HEAD, and 304 reuse one ETag. Duplicate parameters, not-found/conflict, upstream, rate-limit, and server errors remain `no-store`; the change does not make the entire `/api/*` tree cacheable. Query order does not change cache identity, and cookies do not fragment public objects.

### Docs

- **Exact-body conditional-request contract shipped for public RSS and catalog APIs**
  Anime / group / other / magnets RSS and seven catalog APIs now compute an opaque SHA-256 weak ETag from the final JSON/XML UTF-8 bytes; GET, HEAD, and matching-`If-None-Match` 304 responses reuse one cached representation. Public RSS no longer writes a request-time `lastBuildDate`. The `ts` field in `/api/seasons/anime` and `/api/anime/groups` is now the cached representation materialization time and is included in the body and ETag. These endpoints currently omit `Last-Modified`. An unresolved anime owner may still return an empty `200`, an unknown group owner remains `404`, and the three other catalog APIs have not been added to Cloudflare edge eligibility.

The workflow supports Web / BFF and native clients, exact redirect URLs, self-service scopes, one-time zero-overlap secret rotation, suspend / resume, grant revocation, and deletion. Dynamic Client Registration remains disabled. The standalone OIDC documentation module now includes the [overview and field reference](/docs/oidc), [third-party integration guide](/docs/oidc/integration), and [AI / Agent integration reference](/docs/oidc/ai-reference).

See [Sign in to third-party apps with AniBT](/docs/oidc).

## July 30, 2026

### Security

- **Plain-text MediaInfo migration**  
  MediaInfo on release details is now UTF-8 plain text end to end: Web GET/HEAD responses use `text/plain` plus nosniff, and the page renders only text. Production agents now use `mediainfo --Output=Text` and require verified qBittorrent TLS certificates. Every historical `.html` reference and object was converted to readable text and removed with zero legacy residue.

- **RSS output encoding hardening**  
  Markdown links and image URLs in public RSS continue to use separate attribute encoding and safe protocol handling. This RSS boundary is independent from restoring raw HTML on release-detail pages.

### Fixed

- **Raw HTML restored in release notes**  
  Anime and other-release notes, detail pages, and previews once again render Markdown plus raw HTML. Historical layouts using `details`/`summary`, tables, images, links, `div`/`span`/`font`, and inline style remain available. The page renderer applies no sanitizer; editing remains limited to subtitle-group members, administrators, and controlled publishing API keys.

## July 25, 2026

### Fixed

- **Public RSS query order matches CDN cache identity**  
  Magnets, anime, group, and other RSS URLs whose raw query pairs differ only in order now return the same canonical 200; self URL, ETag, and cache identity remain stable, while public RSS currently omits Last-Modified. Defaults, compatibility aliases, and case / whitespace / encoding differences still return 308. Invalid duplicates remain application 400 + no-store, while invalid limit may be blocked first by production Cloudflare 403.

### Security

- **Private-cache contract for personal subscription RSS**  
  Successful, missing/invalid credential, rate-limited, and server-error responses from `/rss/subscriptions.xml` now consistently carry `private, no-store` plus both CDN no-store headers. This private feed does not provide a public ETag or If-None-Match 304 contract.

## July 24, 2026

### Improved

- **Immediate entity-RSS cache invalidation**  
  After publish events invalidate the matching Redis family, public anime, group, and other-category RSS now purge every Cloudflare CDN query variant for the same `bgmId`, `groupSlug`, or category in one operation. URLs, TTLs, ETags, and 304 semantics are unchanged; magnets search and search Redis identities keep their existing TTL behavior.

## July 22, 2026

### Added

- **Anime release deletion API**  
  Added `DELETE /api/releases/{releaseId}` and `GET /api/releases/{releaseId}/deletion`. V1 accepts `rel_*` only; DELETE rejects query parameters and request bodies, returns a stable `rdel_*` receipt, and uses 200/202 for completed/pending. `completed` is emitted only after absence is proven across canonical/detail/torrent reads, Typesense, magnets, public/subscription RSS, Redis, Cloudflare, and AniBT-owned R2 objects. External posts, tracker state, and client-cached content are explicit exclusions. See [Delete releases](/docs/open-api/releases-delete).

### Security

- **Subtitle-group API-key scopes**  
  API keys now explicitly select at least one of `releases:publish` and `releases:delete`; existing keys were safely migrated to `releases:publish` only. Publishing requires `releases:publish`; deletion and status reads require `releases:delete`. `/api/subtitle-groups/me` and publish whoami now expose `apiKeyId`, `apiKeySuffix`, and `scopes`.

- **Auth security and OAuth reliability**  
  Better Auth is now 1.6.23. CAPTCHA tickets use exact path matching and atomic one-time consumption while registration/sign-in bypasses remain closed. KUNGal token exchange uses standard form encoding, and OTP, verification, reset, and welcome mail are durably queued instead of waiting on an external mail provider in the auth request.

### Improved

- **Registration and session restoration**  
  Email registration now runs as send code → atomically verify and create a session → attach the password inside that session. Invalid password format does not consume the code; lost verify/password responses are retryable, and an unexpired flow survives a full-page reload. Public pages show sign-in only after the server explicitly confirms no session, so temporary network/5xx failures no longer create false logout.

## July 21, 2026

### Improved

- **Image batch upload, latency, and progress**  
  Upload preparation handles up to five images in one membership check and one control-plane transaction, while one batch GET and one Convex query now poll every active image together. The R2 PUT ETag travels with the worker job, and one If-Match conditional read replaces staging HEAD requests before and after the body read. Supported browsers pre-scale oversized static JPEG/PNG/WebP files only when the result is meaningfully smaller; animation, HEIC/HEIF, and other skipped formats still go through the worker. The per-image limit remains 10 MiB.

## July 20, 2026

### Improved

- **Direct image upload and isolated transcoding**  
  Subtitle-group image hosting now uploads browser bytes directly to staging R2. The main Web runtime only handles authorization, presigning, object verification, and status queries; it no longer reads image bytes or transcodes them. The shared Bun worker starts a short-lived child per image and uses native `Bun.Image` to write directly to `Bun.S3File`. Damaged or failed static-image transcodes fail explicitly, while animation and SVG remain preserved. See [Image host](/docs/image-host).

## July 19, 2026

### Fixed

- **Fixed tracker URL restored**  
  AniBT has restored `https://tracker.anibt.net/announce` with no signed dual path. Existing AniBT torrents need no URL replacement or data re-download. Magnets, RSS, and canonical `.torrent` downloads now contain exactly one fixed AniBT tracker while preserving the infohash. See [Tracker](/docs/tracker).

### Security

- **Tracker whitelist and edge protection**  
  The fixed `/announce` endpoint still serves only v1 `info_hash` values admitted by AniBT; external hashes receive not whitelisted. Cloudflare retains 20-byte `info_hash`/`peer_id` validation and a basic burst limit. Public `/scrape`, `/api/*`, `/announce/v1/*`, and UDP remain closed.

## July 18, 2026

### Added

- **Site-wide Markdown content negotiation**  
  AniBT public HTML pages now support `Accept: text/markdown` through real-time Cloudflare edge conversion. `Vary: accept` keeps HTML and Markdown cache variants separate, token estimates are exposed, and JSON APIs, RSS/XML, images, and R2 objects keep their native formats. The current public Content-Signal is `ai-train=yes, search=yes, ai-input=yes`.

### Fixed

- **Stable search sorting with text queries**  
  `/magnets` and `/rss/magnets.xml` no longer fail when a text search is combined with sort-by-size or sort-by-episode due to Typesense’s three-sort-field limit. Explicit sort order, publish time, and text-match priority are unchanged.

- **Latin-diacritic title equivalence**  
  Pure-Latin titles keep both the original diacritic token and a folded equivalent, such as Caraméliser / Carameliser; CJK and mixed-script text are not folded. If folding produces candidates from multiple anime, the matcher keeps all of them and fails closed instead of auto-binding the first result.

- **Web manual-upload evidence loop**  
  Web torrent upload now verifies group membership, parses the real `info.name`, and replays v3 server-side; callers cannot forge the project fingerprint. A matcher result that already selects the same anime does not train itself. Manual or different-target confirmation starts pending, a second distinct episode activates, repeated episodes do not increment, and conflicts suspend. Matcher outages, internal exceptions, and oversized `info.name` values do not block an already validated explicit selection and do not learn a binding.

### Changed

- **Strict public RSS request contract**  
  Every public RSS endpoint now accepts exactly one `limit` from 1..100 (default 100); oversized, repeated, empty, zero-padded, or non-integer values are no longer silently truncated. `q`/`search` allow one value total with NFKC, trim, whitespace collapse, and a 160 UTF-8-byte cap. Canonical URLs return a one-day-cacheable 308; invalid input returns application 400 and may be blocked first by production Cloudflare 403.

### Improved

- **High-cardinality search MISS protection**  
  Magnets/other searches and empty results cache for 600 seconds while latest/filter variants cache for 120 seconds. Stable queries and cache HITs do not consume new-query budget. New high-cardinality MISSes use 10-minute/24-hour distinct-query budgets and a global concurrency lease; rejection returns 429 + Retry-After. Redis keys and structured logs retain only query hashes, never raw search text.

### Operations

- **Indexer edge and origin hardening**  
  Normal Jackett, Auto_Bangumi, and ani-rss requests remain compatible. Cloudflare blocks invalid limits at edge, dynamic origin protection remains 500 requests per 10 seconds, and publish invalidation now uses exact URLs instead of clearing every search variant. Front proxies add edge-bypass validation, privacy-safe sampled logs, and reliable rotation.

### Data

- **Matcher generation 2040**  
  Production now uses `match_v3_20260718_2040` with 8,621 anime candidates, 223,792 aliases, and 168 scoped bindings. The fixed 34,083-item corpus has 28,559 automatic decisions (83.7925%); the 2024–2026 subset is 9,084 / 9,807 (92.6277%). Both Carameliser and Caraméliser now auto-match BGM 617123 in production.

## July 17, 2026

### Added

- **Publish API group whoami**  
  `GET /api/releases/publish` and `GET /api/other-releases/publish` return the API key’s bound `groupId` / `groupName` / `groupSlug` / `apiKeySuffix` without writing. Formal publish and preview success responses also echo the same identity fields so automation can detect a wrong-group key before durable write.

- **Official abbreviation alias proposal queue**  
  Admins get `/admin/anime-alias-proposals`. An offline miner clusters latin abbreviation gaps from `low_evidence` failures; proposals must be approved before writing a manual alias and triggering projection sync. Rejected (animeId, normalizedAlias) pairs stay dead. Runtime thresholds are unchanged and nothing auto-writes aliases.

### Fixed

- **Block empty magnet-only formal publishes**  
  When there is no torrent and `fileSize` cannot be resolved to >0 (including magnets without `xl=`), formal publish returns 422 / `reason=EMPTY_RELEASE_CONTENT`. Preview still allows 0 B so operators can check match status and group identity.

### Improved

- **Manual match project fan-out**  
  When a fansub member or admin manually matches a pending release, “remember project” and “also match other pending releases in this project” default on. One confirmation activates the group + `projectFingerprint` scoped binding and retroactively matches up to 64 pending siblings with the same fingerprint. Never crosses groups.

## July 16, 2026

### Added

- **RSS emits `anibt:bgmId`**  
  `/rss/magnets.xml`, `/rss/anime.xml`, and `/rss/group/<slug>.xml` anime items now include `<anibt:bgmId>` (Bangumi subject id when bound) under `xmlns:anibt`. `/rss/other/*` does not. Standard readers can ignore the namespace.

- **Safe non-anime and bundle exits**  
  Standalone PV/CM, MAD/AMV, game videos, concerts, live-action, music albums, stage / reading productions, announcements, wallpapers, and font packages may return `non_anime`. Single-anime single-season packs can still match; multi-anime, true multi-season, and S1+S2+OVA bundles return `unsupported`.

- **Subtitle-group project learning**  
  Explicit confirmation learns per group and project fingerprint: the first confirmation records pending, a second distinct episode pointing at the same anime activates, and Web manual selection can remember immediately; conflicts suspend. The automatic matcher does not train in reverse; active bindings still must pass candidate projection, season/year/format/episode veto, and integrity checks.

### Improved

- **Torrent matcher v3 cutover**  
  The canonical API is hard-cut to `POST /api/animes/torrent-match`. GET returns JSON 405, with no v2 DTO, cache, or compatibility layer. The server parses release title and torrent internal name independently, builds a multilingual AST, and separates exact, strict-recall, and fuzzy-recall retrieval. Season N - EP, bracket version years, mixed scripts, and cross-season continuous episodes are handled; any overflow, cutoff, missing hydration, or generation/projection mismatch blocks automatic binding. See [Torrent match API](/docs/open-api/anime-torrent-match).

- **Episode-boundary and version-year closure**  
  Bare numeric brackets are now contextual: 24 is an episode in `[Title][24][1080p]` and remains frame-rate metadata in `[Title][1080p][24][AAC]`. A `2024年版` / `(2024)` marker must match the candidate premiere year exactly. A one-episode special-count offset is repaired for a boundary episode or exact whole-season range only when family completion, later-season ranking, publication time, and a unique target all agree.

- **One matcher across publishing**  
  Publish UI, bulk publishing, manual matching, and API-key publishing now share the server-side v3 matcher. When no anime ID is supplied, the publish API runs the same decision directly; caller-forged internal match assertions are discarded, and only `decision.kind=auto` binds immediately.

### Data

- **Clean production match index**  
  Production now uses `match_v3_20260716_2112` with 8,621 anime candidates, 223,778 aliases, and 24 scoped bindings. On the fixed 34,083-item corpus, 9,091 / 9,781 anime releases from 2024–2026 are automatic (92.9455%); excluding VCB bundles planned for separate handling, the result is 8,744 / 9,339 (93.6289%). TMDB/TVDB do not participate in matching.

## July 14, 2026

### Added

- **Explainable auto-binding contract**  
  Responses add `decisionReason`, `exactAnimeCount`, `vetoCategory`, and bounded `evidenceSummary`. Clients may automatically use `bestMatch` only when `shouldAutoSelect=true`; shared titles, modifier conflicts, weak evidence, and exact overflow remain manual.

### Improved

- **Torrent-title anime matching**  
  `/api/animes/torrent-match` now uses the dedicated `anime_match_aliases` index to globally disambiguate Chinese, Traditional Chinese, Japanese, romaji, English, multilingual title lists, and Season/Cour/Part/Sequence/Format evidence. The old `allTitles` text-score margin no longer authorizes binding. Long multilingual exact queries now use a request body instead of the Typesense GET query string, avoiding the 4,000-character limit.

  The retired GET matcher once used a 60-second shared cache with stale fallback disabled. The July 16 POST v3 hard cut removed that GET route, v2 DTO, and cache; current matcher responses are always no-store.

## July 12, 2026

### Improved

- **Publish and upload error contract**  
  JSON magnet and multipart torrent failures on the anime and other-release publish APIs now share an `ok=false` error envelope with machine `code`, a safe `message`, optional `reason`, `retryable`, `retryAfterMs`, `requestId`, and i18n metadata. `X-Request-ID` can be used to correlate server logs.

- **Actionable publish status codes**  
  A planned deployment handoff pause now returns 503 Service Unavailable with `Retry-After` and `reason=DEPLOYMENT_IN_PROGRESS`. Duplicate release versions retain 409 with `reason=RELEASE_VERSION_EXISTS`. Write throttling returns 429 with `reason=RATE_LIMITED` and an explicit backoff delay.

## July 11, 2026

### Docs

- **Publish success and public visibility**  
  The documentation now clarifies that a publish API 200 OK means the AniBT write was accepted and downstream work was handed off reliably; it is **not** a synchronous guarantee that the release is already present in RSS, search, public pages, every CDN location, or an external site. Callers should verify the returned `releaseId` in the target body; HTTP 200, `generatedAt`, ETag, or a cache hit alone is not proof of updated content.

### Improved

- **Ordered public snapshot publication**  
  Public magnets, RSS, anime/group/release-detail snapshots, and related pages now use immutable R2 generations plus PostgreSQL publication heads. Web reads and strictly warms only the generation selected by the head; Redis publication-order / generation fences reject stale writeback, and page-ready is emitted only after every required variant completes. Anime updates and deletes continue to handle old/new BGM aliases and affected sitemaps.

- **Reliable Edge invalidation**  
  CDN invalidation now uses a durable URL queue and frozen runs/batches. Token + generation-fenced leases prevent stale executors from acknowledging work; failures resume, corrupt state is quarantined rather than silently discarded, and bounded retention keeps processed markers for 14 days, completed runs for 14 days, and quarantined runs for 30 days.

### Operations

- **Freshness operations gate**  
  Added metrics, alerts, and preflight checks for snapshot queue/claim delay, publication pending/latency, head/watermark integrity, generation maintenance/GC, and Edge D1 durable flush. High queue age with low Redis warm latency is treated as scheduling/backlog; extending TTLs is not an accepted workaround for propagation gaps.
