字幕組圖床位於 `/groups/<slug>/image-host`，選單名稱是 **圖床**。它只對已加入該字幕組組織的成員開放；普通登入使用者和未加入該字幕組的使用者不能上傳、查看管理列表或刪除圖片。

<Callout type="info">
  公開短連 `/i/<shortCode>` 只展示已經上傳的圖片，不提供上傳或管理能力。
</Callout>

## 頁面結構

圖床頁面採用 **單入口上傳 + 下方圖片管理** 的結構，避免頂部模式切換或兩欄上傳面板。上傳區始終在頁面上方，歷史圖庫在下方按時間分頁載入。

- **上傳**：點擊上傳區選擇圖片，也可以拖曳圖片到上傳區，或在頁面中直接貼上剪貼簿圖片。每張圖片會在本次上傳區顯示固定狀態列，直傳階段顯示真實百分比，之後依次顯示準備、已入佇列、校驗與轉碼、收尾和完成。
- **剛上傳**：上傳成功後，複製格式直接顯示在對應結果列，方便馬上貼到論壇、公告或發布說明；批次上傳的檔名、狀態和進度位置保持對齊。
- **圖片管理**：用於瀏覽該字幕組已經上傳的圖片。圖庫使用小縮圖密集網格、懶載入和分頁載入，適合後續管理大量圖片；需要完整 BBCode、HTML、Markdown 與直連時，點選複製格式開啟彈層，不會撐開或打亂圖庫版面。

## 上傳方式

- 支援點選選擇圖片、拖曳圖片到上傳區、在頁面中直接貼上剪貼簿圖片。
- 瀏覽器每批最多提交 5 張的小型 JSON；主站只做一次登入與字幕組成員授權，隨後一次返回該批全部 staging R2 預簽名網址。
- 原始圖片二進位由瀏覽器最多 5 路併發直接 `PUT` 到 staging R2，不使用 multipart/FormData，也不經過 Web runtime；頁面分別顯示每張圖片的真實上傳百分比。上傳完成後，瀏覽器只通知主站排隊處理，物件校驗由 worker 統一完成。
- 頁面會輪詢背景處理狀態；只有 worker 完成轉碼、寫入正式物件並登記中繼資料後，才顯示複製格式。

## 圖片處理規則

| 項目 | 當前規則 |
| --- | --- |
| 輸出格式 | 可解碼的靜態 JPEG/PNG/GIF/BMP/AVIF/HEIC/HEIF 會轉成 `image/webp`；無需縮放的靜態 WebP 校驗後直接保留，超出最長邊時才縮放並重新編碼。靜態圖解碼或編碼失敗時上傳失敗，不保存損壞原圖。 |
| 預設大小上限 | 單張輸入預設 10 MiB，可由部署環境調整。 |
| 預設像素上限 | 解碼後預設最多 50,000,000 像素。 |
| 預設最長邊 | 輸出最長邊預設 3840px，按比例縮小，不放大。 |
| 預設品質 | WebP quality 預設 88。 |
| 服務端併發 | shared worker 預設同時處理 5 張，部署上限 5；每張圖片使用獨立短生命週期 Bun 子程序，全域 worker 併發仍為 8。 |
| SVG | 支援上傳並保留 `image/svg+xml` 原格式。 |
| 動畫 GIF / 動畫 WebP / APNG | 支援上傳並保留原格式，不抽幀、不壓成靜態圖。 |

圖片轉碼和正式物件寫入由 shared Bun background-worker 完成。每張圖片會啟動一個短生命週期子程序：第一次 HEAD 對照準備階段聲明的 size 與 `Content-Type`，讀取後第二次 HEAD 再核對 size、類型和 ETag，防止讀取期間物件被替換。隨後由 `Bun.Image` 完成校驗、自動方向、按需縮放和 WebP 編碼，並直接寫入 `Bun.S3File`。子程序退出後，圖片 native 記憶體由作業系統回收，不會留在長生命週期 Web SSR 程序中。Convex 只保存短期 upload intent、排隊任務和最終中繼資料，不處理圖片二進位或物件儲存 IO。

刪除圖片時，Convex 會先完成權限校驗、軟刪除元資料並投遞 `media/r2_object_delete_batch`，再由 Bun background-worker 使用原生 `Bun.S3Client` 非同步刪除物件。

## 複製格式

上傳成功後，上傳工作區會在結果區生成以下格式：

- BBCode：`[img]https://i.anibt.net/image-host/2026/07/05/Ab3CdE1/pasted-image.webp[/img]`
- BBCode 連結：`[url=https://anibt.net/i/Ab3CdE1][img]...[/img][/url]`
- BBCode 直連：`[url=https://i.anibt.net/image-host/...webp][img]...[/img][/url]`
- HTML：`<img src="..." alt="pasted-image.webp" title="pasted-image.webp">`
- HTML 連結：`<a href="https://anibt.net/i/Ab3CdE1" target="_blank" rel="noopener noreferrer"><img ...></a>`
- HTML 直連：`<a href="https://i.anibt.net/image-host/...webp" target="_blank" rel="noopener noreferrer"><img ...></a>`
- Markdown：`![pasted-image.webp](https://i.anibt.net/image-host/...webp)`
- 直接連結：`https://i.anibt.net/image-host/...webp`；保留原格式時副檔名會是 `.gif`、`.svg`、`.apng` 等對應格式。

## 管理與刪除

圖片管理區域展示該字幕組的歷史上傳。成員可以預覽圖片、複製直連、開啟圖片直連或刪除有權限的圖片；需要全部複製格式時，點選複製格式按鈕開啟彈層。

刪除權限：

- 上傳者可以刪除自己上傳的圖片。
- 字幕組 owner/admin 可以刪除該組圖片。
- 站點管理員可以刪除任意字幕組圖床圖片。

刪除時 Web runtime 會先向 Convex 請求刪除授權和物件 key，再呼叫 Convex 將元資料標記為已刪除並投遞 media worker 刪除任務。圖片會立即從列表和短連查詢中消失；直連物件可能短時間仍可存取，直到 background-worker 完成非同步刪除。

## 管理員近期審查

站點管理員可在 `/admin/image-host` 查看近期上傳的圖床圖片。該頁面按上傳時間展示跨字幕組記錄，並使用密集小縮圖網格，便於快速掃過大量近期圖片並檢查敏感、違規或不適合公開展示的內容。

管理員可以從近期審查頁複製直連、開啟圖片直連、查看完整複製格式，並刪除任意字幕組的圖床圖片。該頁面只對站點管理員開放，不面向普通使用者或普通字幕組成員。

## 部署要求

圖床必須使用獨立物件桶和專用存取金鑰。生產環境需要配置：

| 環境變數 | 說明 |
| --- | --- |
| `IMAGE_HOST_R2_BUCKET` | 圖床專用桶名。 |
| `IMAGE_HOST_R2_ENDPOINT` | S3/R2 endpoint；可填帳號級 endpoint，帶 `/<bucket>` 路徑時會校驗並歸一化。 |
| `IMAGE_HOST_R2_ACCESS_KEY_ID` | 圖床桶 access key。 |
| `IMAGE_HOST_R2_SECRET_ACCESS_KEY` | 圖床桶 secret key。 |
| `IMAGE_HOST_PUBLIC_DOMAIN` | 公開圖片域名；裸域名會自動補 `https://`。由 Convex 控制面生成最終直連。 |
| `IMAGE_HOST_MAX_INPUT_BYTES` | Web、Convex 和 shared worker 的單圖上限；生產為 `10485760`。 |
| `IMAGE_HOST_CONVERT_CONCURRENCY` | shared worker 圖片轉換併發；生產使用 `5`，最大 `5`。 |
| `WORKER_QUEUE_CONCURRENCY_MEDIA` | shared worker 的 `media` 佇列併發；生產使用 `5`。 |

Web runtime 和 shared background-worker 都需要同一套 `IMAGE_HOST_R2_*` 配置；Convex 需要 `IMAGE_HOST_PUBLIC_DOMAIN`。圖床桶還必須允許 `https://anibt.net` 對預簽名網址執行跨來源 `PUT` 並允許上傳所需請求標頭；worker 透過 S3 HEAD 讀取 ETag，不依賴瀏覽器回傳。生產 Docker 映像會在構建階段檢查 `Bun.Image` 和 `Bun.S3Client`；如果執行時不支援這些原生 API，構建會失敗。
